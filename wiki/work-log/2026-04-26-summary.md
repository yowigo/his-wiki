## 主题：打通 his-wiki 与 Claude Code 的自动触发链路

让任意工作目录的新 Claude Code 会话遇到 HIS 任务时，能自动识别信号词、自动 Read 权威源、自动进入开发态——消除"每次会话重新解释 HIS 是什么、ProcessRequest 长什么样、jsonParams 字段差异"的重复成本。

```
触发层（信号识别）：~/.claude/CLAUDE.md 全局触发器 + MEMORY.md 索引
   ↓
中间层（跨目录入口）：~/.claude/projects/.../memory/reference_his_wiki.md
   ↓
知识层（事实来源）：his-wiki/CLAUDE.md + wiki/api/plugin-development.md（已修补）
```

## 决策记录

- **不新建 `wiki/外部接口开发/接口开发指南.md`**：发现 `wiki/api/plugin-development.md` 已存在且覆盖度高，按 CLAUDE.md "禁止双份真理" 原则改为原地修补
- **不每个项目根加 CLAUDE.md（C 方案被否）**：项目数量多、维护成本高、his-wiki 路径硬编码会有 N 处搬迁成本
- **不立刻做 `/his-dev` skill**：先用 B+C 流程跑一两次实际接口开发，验证流程稳定后再固化为 skill，避免把未验证流程刻进可重用资产
- **触发器信号词选高特异性**：`Plugins.EB_*` / `CPAPIPluginBase` / `assimbelyName` / `IInsureInterface` 这种"出现即必然是 HIS"的词，避免和非 HIS 项目的接口讨论混淆
