> 原始资料：`../../raw/外部接口开发/上海医保项目五期/日对账记录查询功能说明.md`、`结算对账使用手册.md`、`五期对账记录表结构.sql`
> 适用项目：`zlchs.SH.GJBYB.insure`（国家医保 + 上海五期双通道）
> 关联页面：[上海医保五期插件](shanghai-5th.md)、[五期 SL01 对账落库失败排查](../troubleshooting/medical-insurance/issue-20260807-sh5-sl01-reconcile-fee-type.md)

## 一、业务背景

医院每完成一笔医保结算，会把结算流水（费用总额、基金支付、个人账户支付等）报到医保中心。**对账** = 医院把「本地汇总结算数据」与「中心记录」逐日核对，确认金额、笔数一致（账平）。

- 医保中心按**对账结果**与医院结付（拨钱）——账不平的日期/险种资金结付受影响。
- 尽早发现漏报、重复报、金额差异、退费未冲正。

**本项目对账分两条线：**

| 线路 | 通道 | 入口 | 交易 |
| --- | --- | --- | --- |
| 国家医保 | CSB HTTP | 菜单 1020 → `Frm结算对帐` | 3201 对总账 / 3202 对明细账 / 9101 文件上传 / 9102 文件下载 |
| 上海五期 | SendRcv4 | 菜单 1021 → `Frm医保五期登记查询对账` | SL01 对账（手工调试式） |

两线共用同一套结算流水数据（按系统区分），但**对账记录只有国家对账会生成**，五期不产生对账记录。

## 二、基本概念

| 概念 | 说明 |
| --- | --- |
| 险种类型 | 310 职工基本医疗保险 / 390 城乡居民基本医疗保险 |
| 清算类别 | 11 门诊 / 21 住院 |
| 清算经办机构 | 本地结算流水中的经办机构编码（03、321099 = 本地直结，其余异地/代办） |
| 账平 / 账不平 | 3201 对总账返回 `stmt_rslt`：`0`=账平，非 `0`=账不平（带原因） |
| 主记录 / 明细记录 | 按「日期」一条主记录，按「险种 × 清算类别 × 经办机构」逐行明细 |
| 对账状态 | `0` 未对账（对账但全不平）/ `1` 已对账（全平）/ `2` 部分对账 |
| 申报状态 | 未申报 / 已申报（申报是后续环节，界面未开放操作） |

## 三、国家对账（Frm结算对帐，菜单 1020）

### 3.1 查总账

选对账日期（单日）→ 查询 → 本地结算流水按 险种 × 清算类别 × 清算经办机构 汇总分行（医疗费总额 / 基金支付 / 个人账户 / 现金支付 / 结算笔数 / 经办机构）。

> 汇总口径：正金额结算 + 退费流水（负金额按「原结帐ID」关联原流水归入原险种/类别），退费不单独成行。

### 3.2 对总账（核心操作）

1. 对每一行调 **3201 对总账**；
2. 返回后该行显示 `账平` 或 `账不平,<原因>`；
3. 结果自动保存：同一天重复对账 = **更新覆盖**；全部处理完弹出 `成功 N 条 / 总计 M 条`；
4. 主记录状态：全平 → 1 已对账；部分平 → 2 部分对账；全不平 → 0 未对账。

⚠️ 只要执行过【对账】记录就产生了（即使全不平状态 0 也保存）；一次对账中只要有一行 3201 失败，本日期对账流程立即中止。

### 3.3 明细对账（核对到每一笔）

选中不平的行 → 对明细：

1. 查本地该行全部结算明细 → 生成 txt → 压缩；
2. 调 **9101 文件上传** 上传压缩包；
3. 调 **3202 对明细账**（附总金额、笔数、清算类别）；
4. 自动调 **9102 文件下载**，把中心明细文件下载解压到本地；
5. 「本地明细」「中心明细」两个表格逐笔核对。

文件位置：本地明细 `程序目录\明细对账文件\<时间戳>\`；中心明细 `程序目录\目录下载\<文件查询号目录>\result.txt`。

### 3.4 对账记录查询

- 查询条件：日期范围（默认本月 1 号~今天）、对账状态（**默认「未对账」**）、险种、清算类别、对账结果。
- 双击主记录 → 明细页看每行本地 vs 中心金额、账不平行标红。
- ⚠️ 前提：**必须先执行过对账，列表才有数据**（记录是对账动作产生的，不是按日期预生成）。

## 四、上海五期对账（Frm医保五期登记查询对账，菜单 1021）

这是一个**接口调试工具**（选交易 → 填参 → 调用 → 看返回），不是批量业务界面：

1. 交易类型选「SL01 对账」；
2. 手填参数（来自当天本地结算汇总）：对账日 yyyyMMdd、中心流水号数量（当天结算笔数）、当年/历年账户支付总额、现金自负总额、统筹支付总额、附加支付总额、分类自负总额、非医保范围费用总额；
3. 调用 → 返回结果展示；
4. ⚠️ **SL01 不产生对账记录**，也不会出现在「对账记录查询」列表；之后如需查明细，用五期 SJ31 等查询交易辅助核对。

> 排查参考：SL01 返回空 → 前置机不可达（检查 `C:\SendRcv.ini` / `C:\SendRcv.dll`）；对账成功但 `daily_reconcile_sh5` 无数据 → 落库失败被 catch 掩盖（SaveSh5Reconcile 已改为影响行数 < 1 即抛异常）。

## 五、数据库表

## 六、常见问题 FAQ

| 问题 | 原因 / 处理 |
| --- | --- |
| 对账记录查询列表没有数据 | 该日期从未执行过【对账】，先到「对账功能」对账 |
| 查「未对账」没有数据 | 正常——`0 未对账` 只在「对账了但全部不平」时出现 |
| 同一天对账多次只有一条 | 重复对账 = 更新覆盖 |
| 中心金额列全是 0.00 | 已知遗留：查询中「中心金额」暂不写数值，不影响核对；逐笔核对以「对明细」表格为准 |
| 对账中途报错中止 | 3201 失败即中止，重试【对账】即可，已成功的行不受影响 |
| 五期对账记录查不到 | 五期 SL01 不产生对账记录，且五期/国家对账记录互不可见 |
| 异地/代办结算 | 总账按「清算经办机构」分行，分开核对互不影响 |

## 七、上线前注意事项

- 对账是面向医保中心的对外交易，金额/笔数直接决定结付——操作前确认日期正确、当天结算完成后再对账。
- 生产首次使用先拿小日期（如昨天）试对，确认账平再铺开。
- 账不平不要反复点对账掩盖问题，先查明细文件定位差异（漏报 / 重复 / 退费未冲正）。
