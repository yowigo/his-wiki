# 北京市电子票据接口实现摘要（0301/0302/0303/0310）

来源文档：`D:\work\his-medical-group\document\北京市电子票据接口\北京市医保信息系统医院端接口服务技术规范V1.08.docx`

适用范围：仅整理报文编号 `0301`、`0302`、`0303`、`0310` 的实现要点，供医院端开发与联调用。

补充：新版本文档 `V1.28废弃了0302，使用0304、0305替代`

## 1. 先选“文档”而不是“skill”的原因

这 4 个接口是固定业务规范沉淀，主要价值是字段对照与联调约束，使用 Markdown 文档更直接、可查、可评审；不需要额外的技能执行流程，因此优先落文档。

## 2. 接口分工与调用方向

- `0301 医保电子票据信息上传`：医院端调用医保端接口（上传医保结算电子发票）。
- `0302 电子票据状态查询`：医院端调用医保端接口（轮询处理状态并获取票据清单 PDF）。
- `0303 全自费电子票据信息上传`：医院端调用医保端接口（上传全自费电子发票）。
- `0310 电子票据明细推送`：医保端调用医院端接口（医保将已处理票据明细推送给医院）。

## 3. 报文级实现建议（最小闭环）

1. 交易完成后生成 `HIS_BIZ_NO`（30位规则：`10位院区编码 + yyyyMMdd + HHmmss + 6位序号`）。
2. 医保结算走 `0301`，全自费走 `0303`，均上传 `ELECT_INVOICE`（PDF Base64）。
3. 医保结算场景可轮询 `0302`，`BIZ_STATUS` 完成后获取 `ELECT_DATA[].SETTLEMENT_DATA`（PDF Base64）。
4. 实现 `0310` 接收接口，落库 `ELECT_DATA` 明细并返回推送结果。

## 4. 接口字段摘要

## 4.1 0301 医保电子票据信息上传（医保提供）

### 输入参数（核心）

| 字段                | 必填     | 类型/长度 | 说明                            |
| ------------------- | -------- | --------- | ------------------------------- |
| `TRADE_NO`        | 是       | C(22)     | 医保交易流水号                  |
| `HIS_BIZ_NO`      | 是       | C(30)     | 医院业务流水号（30位规则）      |
| `CURE_TYPE`       | 是       | C(2)      | 医疗类别：门诊/住院             |
| `ELECT_INVOICE`   | 是       | C         | 电子发票 PDF 的 Base64          |
| `ELECT_XML_TYPE`  | 是       | C(2)      | 电子票据结构类型（带/不带 XML） |
| `ELECT_SETL_INFO` | 条件必填 | 对象      | `ELECT_XML_TYPE=1` 时必填     |

### `ELECT_SETL_INFO` 子字段

| 字段                        | 必填     | 类型/长度 | 说明                                           |
| --------------------------- | -------- | --------- | ---------------------------------------------- |
| `ELEC_SETL_CERT_CODE`     | 条件必填 | C(50)     | 凭证类型=财政票据/税务发票时必填；数电票可不填 |
| `ELEC_SETL_CERT_NO`       | 是       | C(50)     | 电子结算凭证号码                               |
| `ELEC_SETL_CERT_CHK_CODE` | 条件必填 | C(20)     | 规则同 `ELEC_SETL_CERT_CODE`                 |
| `ELEC_SETL_CERT_TYPE`     | 是       | C(20)     | 凭证类型（财政票据/税务发票/税务数电票）       |
| `ELEC_SETL_CERT_FLAG`     | 是       | C(3)      | 票据标识（正常票/冲红票）                      |
| `REL_ELEC_SETL_CERT_CODE` | 条件必填 | C(50)     | 冲红票时必填（原票代码）                       |
| `REL_ELEC_SETL_CERT_NO`   | 条件必填 | C(50)     | 冲红票时必填（原票号码）                       |
| `BILLER`                  | 否       | C(50)     | 开票人                                         |
| `RECHKER`                 | 否       | C(50)     | 复核人                                         |
| `BILL_AMT`                | 是       | N(16,2)   | 开票金额                                       |
| `BILL_DATE`               | 是       | C(10)     | `yyyy-MM-dd`                                 |
| `BILL_TIME`               | 是       | C(8)      | `HH:mm:ss`                                   |

### 输出参数

| 字段             | 必填 | 类型/长度 | 说明                  |
| ---------------- | ---- | --------- | --------------------- |
| `ELECT_STATUS` | 是   | C(2)      | 上传状态（失败/成功） |

## 5. 必做校验清单

- `HIS_BIZ_NO` 长度、格式统一校验（4个接口都依赖）。
- Base64 内容可解码且为 PDF（`ELECT_INVOICE`、`SETTLEMENT_DATA`）。
- `ELECT_XML_TYPE=1` 时，`ELECT_SETL_INFO` 必填（0301）。
- 0303 场景 `ELECT_SETL_INFO` 固定必填（V1.08 更新点）。
- 冲红票时校验 `REL_ELEC_SETL_CERT_CODE/NO` 必填。
- 时间格式严格校验：`BILL_DATE`、`BILL_TIME`、`SELT_TIME`。
- 0310 回调必须幂等（按 `HIS_BIZ_NO + SETTLEMENT_CODE` 去重）。

## 6. 联调注意事项

- 文档中部分状态值以中文说明（如“处理中/已完成”“上传失败/上传成功”），联调时需与医保方确认具体代码值（通常为 `0/1`）。
- 0302 明确“全自费电子票据无 `ELECT_DATA`”，不要按医保结算逻辑强依赖此节点。
- 0310 是医院端暴露接口，建议增加签名/白名单/时间戳防重放机制（按院方网关能力实现）。
