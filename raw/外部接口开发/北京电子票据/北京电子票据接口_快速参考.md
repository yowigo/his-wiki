## 数据流向

```
结算单 (pt_balance.id)
    ↓
    ├─→ 门诊费用明细 (outp_fee_detail) ─→ 医保编码映射 (ins_item_vs)
    │       ↓
    │       └─→ 项目字典 (b_fee_item) ─→ 国家编码
    │       └─→ 药品字典 (b_drug) ─→ 包装单位
    │       └─→ 处方明细 (outp_recipe_detail) ─→ 用法、天数
    │
    ├─→ 住院费用明细 (inp_fee_detail) ─→ 医保编码映射 (ins_item_vs)
    │       ↓
    │       └─→ 项目字典 (b_fee_item) ─→ 国家编码
    │
    ├─→ 诊断 (pt_diagnosis)
    ├─→ 新生儿 (inp_baby) [住院时]
    ├─→ 发票 (nn_invoiceresult) ─→ PDF地址
    └─→ 上传日志 (elect_bill_upload_log)
            ├─→ 医院业务流水号 (his_biz_no)
            ├─→ 上传状态 (upload_status)
            └─→ 结算清单 (elect_bill_settlement)
```

## 常用 SQL 片段

### 获取最新发票
```sql
SELECT DISTINCT ON (r.balance_id)
    r.balance_id, r.invoiceno, r.pdfurl, r.checkcode
FROM insur.nn_invoiceresult r
WHERE r.balance_id = @balanceId AND r.status = '2'
ORDER BY r.balance_id, COALESCE(r.stateupdatetime, r.updatetime, r.createtime) DESC
```

### 获取费用明细 + 字典
```sql
SELECT ofd.*, bfi.country_code, bd.unit as pack_unit
FROM public.outp_fee_detail ofd
LEFT JOIN qw_base.b_fee_item bfi ON bfi.id = ofd.fee_item_id
LEFT JOIN qw_base.b_drug bd ON bd.id = ofd.fee_item_id
WHERE ofd.balance_id = @balanceId
```

### 获取处方用法和天数
```sql
SELECT to_jsonb(ord)->>'method_id' as usage, to_jsonb(ord)->>'days' as days
FROM public.outp_recipe_detail ord
WHERE to_jsonb(ofd)->>'recipe_id' = to_jsonb(ord)->>'recipe_id'
  AND (COALESCE(to_jsonb(ofd)->>'sno', '') = ''
       OR COALESCE(to_jsonb(ord)->>'sub_sno', '') = COALESCE(to_jsonb(ofd)->>'sno', ''))
LIMIT 1
```

### 获取新生儿标志
```sql
SELECT CASE WHEN EXISTS(SELECT 1 FROM public.inp_baby WHERE visit_id = @visitId)
       THEN '1' ELSE '0' END as neonate_flag
```

### 获取现金支付金额
```sql
SELECT CAST(NULLIF(ib.swap_info->>'现金支付金额', '') AS numeric) as psn_cash_pay
FROM insur.ins_balance ib
WHERE ib.balance_id = @balanceId
```

## 数据类型转换

| 场景 | 原类型 | 目标类型 | 函数 | 示例 |
|------|--------|---------|------|------|
| 数字 → 字符串 | NUMERIC | VARCHAR | ::text | `(12345)::text` |
| 时间 → 字符串 | TIMESTAMP | VARCHAR | TO_CHAR | `TO_CHAR(time, 'YYYY-MM-DD HH24:MI:SS')` |
| 字符串 → 数字 | VARCHAR | NUMERIC | ::numeric 或 CAST | `'123.45'::numeric` |
| JSONB 取值 | JSONB | VARCHAR | ->> | `jsonb_field->>'key'` |
| Base64 编码 | BYTEA | VARCHAR | encode | `encode(bytea_field, 'base64')` |

## 常见问题对应字段

**Q: 如何确定就诊类型（门诊/住院）?**
A: `pt_balance.module_source`: 1=门诊，2=住院

**Q: 如何判断是医保还是自费?**
A: `pt_balance.ins_id`: NULL/0=自费，非0=医保

**Q: 费用如何分类?**
A: 使用 `outp_fee_detail.invoice_fee` 进行字符串匹配

**Q: 医保编码在哪里?**
A: `insur.ins_item_vs.ins_item_code`，通过 `fee_item_id` 关联

**Q: 处方信息在哪里?**
A: `public.outp_recipe_detail`，通过 `recipe_id` 关联（需跨域查询）

**Q: 发票信息在哪里?**
A: `insur.nn_invoiceresult`，选最新的 status='2' 记录

**Q: 上传状态怎么追踪?**
A: `insur.elect_bill_upload_log`，按 `balance_id` 查询最新记录

**Q: 结算清单PDF在哪里?**
A: `insur.elect_bill_settlement.settlement_data`，Base64 编码

## 关键限制和假设

1. **无 dosage 字段**: fee_detail 表中无 dosage，需从 recipe_detail 通过 LATERAL JOIN 获取
2. **无 discharge_take_drug_flag**: inp_fee_detail 中无此字段，代码固定为 "0"
3. **无 dose_type**: b_drug 虽有此字段，但代码中未使用，固定为 ""
4. **无 conver_rate**: 代码中固定为 "1"
5. **JSONB 存储**: outp_recipe_detail 的多个字段使用 JSONB 格式，需用 ->> 操作符
6. **跨域无 JOIN**: outp_recipe_detail 在 outpatient 域，无法直接 JOIN
7. **时间字段**: invoicetime 可能是 VARCHAR 或 TIMESTAMP，需 TO_CHAR 转换
8. **PDF URL**: 有多个备选字段（pdfurl > paperpdfurl > pictureurl），需逐个检查

## 命名约定

### 北京电子票据接口报文类型
- **0101**: 未医保结算门诊交易上传
- **0103**: 住院费用结算上传
- **0301**: 医保结算门诊电子票据上传
- **0303**: 自费电子票据上传
- **0304**: 电子结算凭证处理进度查询
- **0305**: 电子结算凭证处理结果查询

### 表字段命名模式
- `*_time`: 时间戳
- `*_code`: 代码字段
- `*_name`: 名称字段
- `*_id`: ID 关联字段
- `invoice_*`: 发票相关
- `his_*`: HIS 系统字段

## 性能建议

1. 查询费用明细时，始终加 `WHERE balance_id = @balanceId`
2. 查询发票时，始终加 `AND ir.status = '2'`
3. 定期清理超过 90 天的 elect_bill_upload_log 记录
4. 使用 DISTINCT ON 避免重复，而不是 GROUP BY
5. outp_recipe_detail 的 LATERAL JOIN 性能开销大，考虑缓存
