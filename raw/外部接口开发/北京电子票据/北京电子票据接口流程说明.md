# 北京电子票据接口 - 业务流程说明

## 一、整体架构

```
HIS工作站
  │
  ├─ 手动操作 ──→ BillQueryForm（查询界面）
  │                  ├─ 查询票据列表（QueryBillData）
  │                  ├─ 批量上传（UploadBills）
  │                  └─ 查询状态（0304→0305 自动衔接）
  │
  ├─ 接口调用 ──→ ProcessRequest（func_sign 路由）
  │                  ├─ 0301  医保票据上传
  │                  ├─ 0303  自费票据上传
  │                  ├─ 0304  查询结算清单生成状态
  │                  ├─ 0305  获取结算清单文件
  │                  ├─ QueryAndGetSettlement（0304+0305 一步完成）
  │                  └─ 0302（兼容旧入口 → 自动转 QueryAndGetSettlement）
  │
  └─ 定时器 ────→ ProcessPendingSettlements（批量轮询，自动完成未处理记录）
```

## 二、报文接口说明

| 报文编号 | 名称 | 方向 | 说明 |
|---------|------|------|------|
| 0301 | 医保电子票据信息上传 | HIS → 医保 | 医保结算后上传电子发票PDF |
| 0302 | ~~电子票据状态查询~~ | - | **V1.28已废弃**，自动转为 0304+0305 |
| 0303 | 全自费电子票据信息上传 | HIS → 医保 | 自费结算后上传电子发票PDF |
| 0304 | 结算清单生成状态查询 | HIS → 医保 | 查询清单是否生成完成，获取 ELEC_SSR_CODE |
| 0305 | 结算清单文件获取 | HIS → 医保 | 用 ELEC_SSR_CODE 拉取结算清单PDF |

## 三、核心流程

### 流程1：票据上传（0301 / 0303）

```
传入 billNo（结算记录ID）
  │
  ├─ GetBillDetail：从 pt_balance 查结算记录
  │    └─ 未找到 → 报错"未找到结算记录"
  │
  ├─ GetInvoicePdfBase64：获取电子发票PDF（Base64）
  │    ├─ 优先从 nn_invoiceresult 查 pdfurl
  │    ├─ 如果是 URL → HTTP下载并转Base64
  │    ├─ 如果已是 Base64 → 直接使用
  │    └─ 都没有 → 报错"未找到电子发票PDF数据"
  │
  ├─ 判断结算类型：
  │    ├─ 医保（ins_id 非空）→ Build0301Input → 调用 0301
  │    └─ 自费（ins_id 为空）→ Build0303Input → 调用 0303
  │
  ├─ 如果 HIS_BIZ_NO 为空 → 自动生成（10位院区编码+时间戳+序号）
  │
  ├─ SM4加密 → HTTP POST → SM4解密响应
  │
  └─ RecordUploadLog：写入 elect_bill_upload_log
       ├─ upload_status = 1（成功）或 0（失败）
       └─ process_status = -1（未处理）
```

**入参方式：**
- 简单模式：只传 `{"billNo": "12345"}`，插件自动从数据库组装全部字段
- 完整模式：传完整的 0301/0303 入参 JSON

### 流程2：查询状态并获取清单（QueryAndGetSettlement）

这是最常用的流程，0304+0305 自动衔接，一次调用完成。

```
传入 billNo 或 HIS_BIZ_NO
  │
  ├─ 如果传 billNo：Build0304Input 查找 HIS_BIZ_NO
  │    ├─ 记录不存在 → "未找到结算记录"
  │    └─ HisBizNo 为空 → "尚未上传电子票据，请先完成上传再查询状态"
  │
  ├─ 第一步：调用 0304 查询生成状态
  │    └─ 更新 elect_bill_upload_log.last_query_time
  │
  ├─ 判断 BIZ_STATUS：
  │    ├─ "0"（处理中）→ 返回"结算清单尚在生成中，请稍后再试"
  │    ├─ "1" 但 ELEC_SSR_CODE 为空 → 返回"已生成但获取码为空，请联系医保中心"
  │    └─ "1" 且有 ELEC_SSR_CODE → 继续第二步
  │
  ├─ 第二步：调用 0305 获取结算清单文件
  │    └─ 传入 HIS_BIZ_NO + ELEC_SSR_CODE
  │
  ├─ 保存结果：
  │    ├─ SaveSettlementPdf → 本地 ElectBills/{HIS_BIZ_NO}/*.pdf
  │    └─ SaveSettlementData → 写入 elect_bill_settlement 表（防重复）
  │
  └─ 更新 elect_bill_upload_log：
       ├─ process_status = 1（已完成）
       └─ settlement_data_count = N
```

### 流程3：UI 界面操作（BillQueryForm）

```
┌──────────────────────────────────────────┐
│  查询票据列表                              │
│  ┌──────┬──────┬──────┬──────┬──────┐    │
│  │ 票据号 │ 患者  │ 金额  │上传状态│处理状态│    │
│  ├──────┼──────┼──────┼──────┼──────┤    │
│  │ 1001 │ 张三  │ 150  │ 已上传 │ 已完成 │    │
│  │ 1002 │ 李四  │ 200  │ 已上传 │ 处理中 │    │
│  │ 1003 │ 王五  │ 80   │ 未上传 │ 未处理 │    │
│  └──────┴──────┴──────┴──────┴──────┘    │
│                                           │
│  [批量上传]  [查询状态]                      │
└──────────────────────────────────────────┘
```

**批量上传：**
1. 勾选记录 → 调用 UploadBills
2. 逐条上传，根据结算类型自动选择 0301/0303
3. 返回成功/失败计数 + 每条失败的具体原因

**查询状态：**
1. 选中一条记录 → 点击"查询状态"
2. 前置校验：未上传 → 直接提示"请先完成上传"，不发请求
3. 调用 0304 查询
4. 如果已完成 → 自动调 0305 获取文件并保存
5. 更新表格显示

### 流程4：定时批量轮询（ProcessPendingSettlements）

HIS 定时器定期调用，自动完成所有待处理记录。

```
HIS 定时器（建议间隔 30~60 秒）
  │
  ├─ QueryPendingProcessLogs 查询满足条件的记录：
  │    ├─ upload_status = 1（上传成功）
  │    ├─ process_status IN (-1, 0)（未处理或处理中）
  │    └─ last_query_time + pollingInterval < NOW()（满足轮询间隔）
  │
  └─ 逐条处理：
       ├─ 0304 查询 → 已完成 + 有获取码 → 0305 获取 → 保存 → 标记完成
       ├─ 0304 查询 → 未完成 → 仅更新 last_query_time
       └─ 异常 → 记录失败详情，跳过继续下一条
```

**入参示例：**
```json
{"pollingIntervalSeconds": 30}
```

## 四、数据流向

```
pt_balance（HIS结算记录） ─────────────────────────┐
nn_invoiceresult（财政发票结果） ──┐                  │
nn_invoiceinfo（发票信息） ────────┤                  │
                                  ↓                  ↓
                       GetBillDetail + GetInvoicePdfBase64
                                  │
                     ┌────────────┴────────────┐
                     ↓                         ↓
              0301 医保上传               0303 自费上传
                     │                         │
                     └────────────┬────────────┘
                                  ↓
                   elect_bill_upload_log（上传记录）
                     upload_status = 1, process_status = -1
                                  │
                          0304 查询状态
                                  ↓
                     process_status = 0（处理中）
                     last_query_time = NOW()
                                  │
                        0305 获取文件（需要 ELEC_SSR_CODE）
                                  ↓
                ┌─────────────────┼─────────────────┐
                ↓                 ↓                  ↓
     本地 PDF 文件         elect_bill_settlement   elect_bill_upload_log
     ElectBills/            （结算清单数据）        process_status = 1
     {HIS_BIZ_NO}/          防重复写入            settlement_data_count = N
     *.pdf
```

## 五、数据库表结构

### elect_bill_upload_log（上传记录表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 自增主键 |
| balance_id | BIGINT | 关联 pt_balance.id |
| his_biz_no | VARCHAR(30) | 医院业务流水号（唯一） |
| trade_no | VARCHAR(50) | 医保交易流水号 |
| bill_no | VARCHAR(50) | 票据号 |
| settlement_type | VARCHAR(20) | 医保/自费 |
| msg_type | VARCHAR(10) | 0301/0303 |
| upload_status | SMALLINT | -1失败, 0未上传, 1成功 |
| upload_time | TIMESTAMP | 上传时间 |
| process_status | SMALLINT | -1未处理, 0处理中, 1已完成 |
| process_time | TIMESTAMP | 处理完成时间 |
| last_query_time | TIMESTAMP | 最后查询时间（控制轮询频率） |
| settlement_data_count | SMALLINT | 结算清单数量 |

### elect_bill_settlement（结算清单数据表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 自增主键 |
| his_biz_no | VARCHAR(30) | 关联 upload_log.his_biz_no |
| settlement_code | SMALLINT | 1门诊/2住院清单/3住院结算单/4特殊病 |
| settlement_name | VARCHAR(100) | 票据名称 |
| settlement_data | TEXT | PDF Base64 |
| create_time | TIMESTAMP | 创建时间 |

**唯一约束：** `(his_biz_no, settlement_code)` 防止重复获取时产生重复数据

## 六、异常处理与提示

| 场景 | 提示信息 | 处理方式 |
|------|---------|---------|
| 结算记录不存在 | "未找到结算记录：{billNo}" | 阻断，返回错误 |
| 未上传就查状态 | "{billNo}（{患者姓名}）尚未上传电子票据，请先完成上传再查询状态" | 阻断，返回错误 |
| UI 未上传点查询 | "该结算记录尚未上传电子票据，请先完成上传再查询状态" | 前置拦截，不发请求 |
| 清单尚在生成中 | "结算清单尚在生成中，请稍后再试" | 正常返回，等待下次查询 |
| 已完成但获取码为空 | "结算清单已生成但获取码(ELEC_SSR_CODE)为空，请联系医保中心" | 正常返回，需人工介入 |
| PDF保存失败 | 写日志，不阻断主流程 | 数据库已保存，可从DB恢复 |
| 上传日志写入失败 | 写日志，不阻断上传结果 | 上传已成功，日志可补录 |
| 批量上传单条失败 | 记录 billNo + 错误原因，继续处理下一条 | 返回汇总 + 每条失败详情 |
| 结算清单重复获取 | SQL 层面防重复（WHERE NOT EXISTS） | 不会产生重复数据 |

## 七、加密通信

所有报文均采用 SM4 国密加密：

```
请求流程：
  明文 = MSG_NO + MSG_TYPE + JSON入参
  → SM4/ECB/PKCS7 加密（密钥取前16字节，UTF8编码）
  → Base64编码
  → 放入请求体 IN_DATA 字段

响应流程：
  取 OUT_DATA 字段
  → Base64解码
  → SM4/ECB/PKCS7 解密
  → 去除 MSG_NO + MSG_TYPE 前缀
  → JSON反序列化
```

## 八、接口兼容性（0302 → 0304+0305）

| 原调用方式 | 现行为 | 兼容性 |
|-----------|--------|--------|
| `func_sign = "0302"` | 自动转为 QueryAndGetSettlement | 兼容，一步完成查询+获取 |
| `func_sign = "QueryElectBillStatus"` | 同上 | 兼容 |
| 传 `{"billNo": "xxx"}` | 自动查 HIS_BIZ_NO 再走 0304+0305 | 兼容 |
| 传 `{"HIS_BIZ_NO": "xxx"}` | 直接走 0304+0305 | 兼容 |

**与原 0302 的差异：**
- 原 0302 一次请求返回状态+文件，现在拆分为两步（0304查状态 + 0305取文件）
- 通过 QueryAndGetSettlement 封装，对调用方透明，仍然是一次调用返回结果
- 返回结构新增 `message` 字段，原有字段保持不变
