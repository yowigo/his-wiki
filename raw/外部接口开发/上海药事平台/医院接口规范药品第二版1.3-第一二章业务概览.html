本页基于《医院接口规范药品第二版1.3》第一、二章整理，目标是快速看清医院 HIS、市药事平台、药企供货方之间的业务关系、关键术语、流程红线与系统对接方式。字段、接口报文和代码字典仍以原规范第三、四章为准。

先看对接方式：同一套业务有两条入口，重心不同

一、IE 访问市药事系统中心 WEB 应用 重心在平台。医院业务人员通过医院内网终端直接操作市药事系统页面，完成药品基础信息查询下载、配送企业查询、价格查询、配送点申报、供货药企库存查询、询价报价等需要人机交互的功能。

二、HIS 侧开发职责速览

本节是医院 HIS 接口开发视角的职责地图；详细执行项仍以开发任务清单为准。
HIS 开发不是实现药企配送系统，也不是实现市药事平台审核规则，而是把医院药库业务变成平台可审核、可流转、可对账、可监管的数据闭环。

HIS 开发侧重点：

  • 维护本地药品、供应商、配送点与平台编码之间的映射。
  • 完成订单提交、订单确认、平台订单编号和本地状态保存。
  • 从平台取回配送单、发票和明细，支撑医院验收、入库和财务入账。
  • 把配送验收、发票验收、支付确认、库存和账务数据按规范回传平台。
  • 遇到超时、重复提交、状态不一致时，用状态查询接口做补偿和人工对账支撑。

对接底座

把 HIS / 药库系统稳定接入市药事平台消息传输服务。

  • 实现 SOAP SendRecv 调用、医保前置机网络连通和平台账号配置。
  • 构造 HEAD、MAIN、DETAIL 三段式 XML，处理字段大小写、必填、字典值和编码。
  • 完成 SHA-1 签名、响应解析、错误码处理、超时、日志、重复提交和幂等控制。

基础数据

先把平台后续下单和配送需要依赖的医院基础信息准备好。

  • YY001：同步医院配送点、药库、药房、科室、配送地址等基础信息。
  • YY002：定时上报药品当前库存，每批不超过 500 条。
  • 维护 HIS 药品、供应商、配送点、库存账务数据与平台字段之间的映射。

采购主链

把医院采购单变成平台认可的有效订单。

  • YY009：提交订单填报；一份订单只对应一家药企和一个配送地址。
  • YY010：用平台返回的订单编号做确认，确认后订单才生效。
  • YY022：医院有仓位管理要求时，用带仓位信息的订单填报承接 YY009 场景。

配送、发票、验收、支付

药企上传业务数据后，HIS 从平台取回并完成院内闭环。

  • YY005 / YY006：查询配送单和配送明细，支撑扫码或录码验收入库。
  • YY007 / YY008：查询发票单和发票明细，避免医院重复录入发票内容。
  • YY018 / YY019 / YY017：配送明细验收、发票验收、支付确认和对账闭环。

异常补偿

处理接口超时、重复提交、状态不一致和人工对账问题。

  • YY020：单条单据通用查询，作为状态核查和补偿入口。
  • YY021：订单明细状态查询，跟踪订单执行情况。
  • YY023：配送单或发票明细状态查询，辅助验收、发票和对账排错。

按需启用业务

根据医院管理模式和业务权限决定是否纳入本期开发。

  • YY011 / YY012：退货单填报和确认。
  • YY024 / YY025：特需药品申报和查询。
  • YY032 / YY033 / YY034：代填企业管理、已设置代填企业查询、发票拒收。

三、第一章业务术语

订单

货品需方向供方提交的采购单据，可来自医院采购计划，也可由库存策略自动生成。订单可以是一品一单，也可以是多品一单。

  • 一份订单只能对应一家供货或配送药企。
  • 一份订单只能对应一个供货配送地址。
  • 涉及多家药企或多个配送地址时，必须拆成多份订单。

配送单

药企根据订单安排配送、装运、装箱的货品清单。配送单必须在配送货物之前上传平台，并且必须早于发票。

  • 配送单用于医院清点验收入库，不等同于发票。
  • 配送数量可小于或等于订单数量，不允许大于订单数量。
  • 配送内容需有条码或唯一标识，供医院从平台获取明细。

发票

药企基于供货情况向医院要求付款、医院财务记账的依据。发票必须明确关联配送数据，平台会实时核对。

  • 必须先有配送，才能编制发票。
  • 发票不是药品验收入库时清点货品数量的依据。
  • 量价挂钩集中采购药品必须单独开票，不能混入其他模式药品。

生产批号

生产企业识别同一批产品的一组编号，用于追溯生产历史、质量状况和市场去向。

  • 配送明细要求按相同生产批号归理。
  • 同一药品如存在不同批号，应拆成不同配送明细。

生产日期与有效日期

生产日期表示商品完成生产工序的日期；有效日期表示在规定储存条件下保证质量使用的最晚日期。

  • 平台采集这些信息用于跟踪医院进货和后续使用情况。
  • 核心目标是质量控制、追溯和必要时的控制或回收。

退货、换货、验收的边界

退货只针对已验收入库货品；尚未验收入库的货品不能作为退货处理。平台不支持换货的信息化流程。

  • 换货可通过先验收入库再走退货，或线下人工处理。
  • 验收按配送明细全收或全不收，不支持同一明细部分数量入库。

四、三种采购模式

模式 谁主导 业务特点 对系统的影响
量价挂钩集中采购 政府按全市定点医院使用情况与药企整体采购，并存在财政预先垫付关系。 平台必须掌握供货方库存、配送在途、收货入库、支付结算等完整账务数据。 平台形成虚拟库存；医院到货后扣减；发票和支付必须单独处理；药企需应对向市药事所回款流程。
招标入围限价供货 政府通过招标确定入围供货最高限价或供货药企，采购主体通常仍是医院。 医院按政府规则通过系统向药企下订单完成采购。 平台承担规则、限价、入围供货方和订单转发监管角色。
不招标 / 挂网询价 医院与药企双方通过网上询价、报价协商。 询价完成后，双方按商定价格和数量交易。 平台提供交易留痕、价格和规则查询、询报价协同入口。

五、医院药库药房业务与平台边界

药库职责

  • 维护药品基础信息、价格信息、新药申报。
  • 采购药品，编制并发送订单。
  • 管理库存或虚拟库存。
  • 处理入库、出库、验收、退货、记账、盘点、报损。

药房职责

  • 从药库领药，或直接接收供货配送入药房。
  • 根据医嘱或处方配置、发放药品。
  • 处理住院、门诊配药记账。
  • 执行盘点、报损、未用药品退回等业务。

医院药库的四种运作模式

1. 医院自设药库

医院自行采购，货品先入药库，再按需配送院内各药房。规范认为这是当前多数模式。

2. 药库业务外包给配送企业

医院不设药库，由外包方按各药房存量组织供货商补充所需。

3. 区县或集团统一虚拟药库

医院不设药库，由区卫生局、医疗集团或医联体统一设置虚拟药库，药企直接配送到医院药房。

4. 药库药房全套外包托管

药库和药房业务均由外包方承担，门诊、住院配药流程由托管体系支撑。

规范的关键口径：无论药库由谁承包或承担，逻辑上仍视为“医院药库”。与市药事系统互联互接的责任随药库承包者或承担者转移，但业务归属仍在医院体系内。
平台边界：市药事系统与医院系统对接围绕药库业务，包括药品基础信息、订单、配送验收入库、发票凭证入账、库存账务。与医院非药品进销存业务暂无关。

七、不能省略的业务红线

先订单，后配送。 所有供货配送必须先有订单，平台不支持事后补订单。
订单必须二次确认才生效。 首次提交只生成订单编号；未确认的订单不生效，相同订单编号重复提交会被拒绝。
审核通过并安排配送后不能撤销。 已提交且审核通过的订单如发现错误，原则上走退货流程。
多品一单，一项不过整单退回。 多品一单中任一品目明细未获审核通过，整张订单退回，不提交供货方。
配送数量不能大于订单数量。 配送可少于或等于订单数量；如需超出，应另行编制订单。
配送单必须早于发票。 药企必须先传配送单，再传对应发票，发票明细需与配送内容吻合。
发票不是验收入库依据。 发票用于财务记账和付款，验收入库依据是配送单及其明细。
同一配送明细按批号归理。 一条明细中的货品批号应相同，不同批号应分列不同明细。
验收不支持部分数量。 同一配送中的某品规明细要么全部收下，要么全部未收下。
退货只针对已验收入库货品。 退货需先填报退货单，退货后由药企提交相应红字发票。
平台不支持换货信息化处理。 实际换货可先入库后退货，或走线下人工流程。
量价挂钩采购必须独立结算。 发票和支付不能与非该模式药品混在一起；平台按 30 天结算周期对账。

八、第二章：医院与市药事系统的对接方式

联网通道

医院通过医保前置机、医保网与市药事系统联网。根据业务内容和医院信息系统现状，规范允许两种方式并存。

两类入口

一类是医院系统调用消息传输接口；另一类是医院内网终端通过 IE 访问市药事系统中心 WEB 应用，完成必须有人机交互的功能。

方式 适用场景 医院侧改造重点 结果
消息传输方式 适合医院药库信息系统支撑的业务数据交换，如订单、配送、发票、验收、支付、库存等。 按第三章规定的消息格式组织数据，调用平台消息传输服务，处理平台返回结果。 数据进入中心端，或从中心端获取业务信息，实现系统对系统集成。
医院内网 IE 访问中心 WEB 适合需要人在界面上查询、下载、申报、询价、报价等业务操作。 在医院内网终端通过 IE 访问指定地址，使用中心 WEB 功能。 不一定改造 HIS 接口，由业务人员直接在平台页面完成交互。

十、医院内网 IE 访问中心 WEB 的业务范围

这类业务强调人工界面操作，不一定通过 HIS 系统接口直接集成。

查询与下载

  • 药品基本信息查询、下载。
  • 中标药品配送企业基本信息查询、下载。
  • 药品在本市范围的最近实际销售价格查询。
  • 供货药企库存情况查询。

申报与交易平台

  • 医院配送点申报。
  • 供销双方在开放式交易平台查询药品品规基础信息、业务规则信息、销售价格。
  • 医院发起询价，药企提供报价，并按规则开展交易。
实现视角：医院 HIS 插件优先覆盖消息传输方式中的高频链路；中心 WEB 更像补充入口，用于查询、下载、申报、询报价等需要人工交互的业务。
