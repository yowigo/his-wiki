## 二、关键发现：insureOrgCode 覆盖问题 🚨

**`Cls_GDSZSZ.cs` 第 73 行：**

```csharp
insureOrgCode = dtOrg.Rows[0]["医院编码"].ToString();  // 第 67 行：取到真正的医院编码
userid = dtOrg.Rows[0]["登录账号"].ToString();
insureOrgCode = userid;  // 第 73 行：立即被覆盖为登录账号！
```

**影响**：所有使用 `Cls_GDSZSZ.insureOrgCode` 拼装 XML 的地方，`<akb020>` 实际发送的是**登录账号**（如 `SA0003`），而不是真正的 H/P 码（如 `H44010400356`）。

**涉及 function_id**（门诊 + 住院 + 交易补偿 + 码表，约 20 个）：
bizh110001/102/104/105/106, bizh120002/003/004/102/103/104/105/106/107/108/109, bizh120205

**不受影响的**：病案首页直接从 `DataHelpers.getybxx()` SQL 取 `iov.ins_code`，不走 `insureOrgCode`。

**已改为注释**，待实测验证。
