# 医院部署前置配置清单

> 本文档整理首次部署上海医保五期/国家医保插件时，必须提前准备的数据库配置和 HIS 基础数据。
> 未完成以下配置，门诊结算流程将在对应环节报错中止。

## 一、部署路线图

```
1. 执行 DDL 脚本：insur 25 张表 + 日对账表（见第二章）
2. 配置 ins_system + ins_system_mapping（见第三章）
3. 配置 ins_org_vs 保险医院对照（见第四章，决定 fixmedins_code）
4. 导入医保目录 → 项目对码（ins_item + ins_item_vs，见第五、六章）
5. 配置 insure_config（url、xzqh 等，见第七章）
6. 配置科室对照（ins_standard_dept* 四张表，见第八章）
7. 配置医护人员编码（b_staff.healthcare_code，见第九章）
8. HIS 结算方式管理配置三条医保结算方式（见第十章）
9. 导入疾病类型字典（按需，见第十一章）
10. 联调验证 InitInsure → ItemMarking → 预结算 → 正式结算 → 日对账 全链路
   联调期遇到 InitInsure 报错对照第十四章卡点表反查
   联调期怀疑 HIS 基础数据问题参考第十三章排错指南
```

## 二、DDL 准备

**前置**：以下 DDL 脚本必须在所有 INSERT 操作之前执行，否则后续所有"插入字典/配置"步骤会报 `relation "insur.xxx" does not exist`。

> 执行域：**fee**

🚨 必须执行的脚本：

| 脚本                             | 内容                                                                                                                                                                                                                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `docs/insur_补表_创建脚本.sql` | 25 张`insur.*` 业务表（含 `insure_config`、`sign_info`、`ins_log`、`ins_system`、`ins_system_mapping`、`ins_item*`、`ins_archive*`、`ins_visit`、`ins_balance*`、`ins_fee_detail`、`ins_reg_record`、`ins_standard_dept*` 等）。注：`insur.ins_org_vs` 由 HIS 标准 schema 提供，本脚本不再重复建表 |
| `docs/日对账记录表结构.sql`    | `daily_reconcile_main` / `daily_reconcile_detail` 两张对账表                                                                                                                                                                                                                                                               |

⚠️ 以下两张表虽不需要预置数据，但**必须在脚本执行后立即存在**，否则插件运行立即异常：

| 表                  | 写入触发点                                    | 缺表表现                                        |
| ------------------- | --------------------------------------------- | ----------------------------------------------- |
| `insur.ins_log`   | `DBLoggingInterceptor` AOP 自动写入         | 每一笔国家医保 CSB 交易都异常（写日志阶段抛错） |
| `insur.sign_info` | `InitInsure` 签到流程（`9001` 接口）读/写 | HIS 客户端启动签到失败                          |

> 验证方法：执行 `SELECT count(*) FROM information_schema.tables WHERE table_schema='insur';`，结果应 ≥ 26（本脚本贡献 25 张，外加 HIS 标准 schema 提供的 `ins_org_vs`）。

**表**：insur.ins_system、insur.ins_system_mapping
**报错**：`获取保险系统映射配置失败！`
**触发时机**：门诊医生站保存医嘱时调用 `ItemMarking`（医保打标）
**根因**：表为空，代码查询 `mapping_sno=10` 无结果

🚨 **需写入 2 条记录**：五期和国家各自的 `ins_id` 映射到 `mapping_sno=10`，`mapping_insid` 填自身的 `ins_id`。

INSERT INTO insur.ins_system (id, sno, name, interface_name, is_unuse) VALUES

## 四、保险医院对照

**表**：insur.ins_org_vs
**报错**：`当前机构未进行保险医院对照-国家医保!` 或 `当前机构未进行保险医院对照-五期医保!`
**触发时机**：HIS 客户端启动调用 `InitInsure`，在查 `insure_config` **之前**就要查它（国家+五期各查一次，见 `Cls_SHGBYB.cs:79,89`）
**根因**：`insur.ins_org_vs` 表中缺少当前机构的对照记录

🚨 每个启用医保的机构必须有两条记录（国家+五期各一条）。返回的 `ins_code` 即**定点医疗机构编码（fixmedins_code）**，后续所有医保交易报文都要带；`org_name` 是定点机构名称，用于报文里的医院名字段。

> 执行域：**fee**

```sql
INSERT INTO insur.ins_org_vs (ins_id, org_id, org_name, ins_code) VALUES
('5388135717170938973', '1', '<定点机构名>', '<国家定点医疗机构编码>'),  -- 国家医保
('5380194289529592754', '1', '<定点机构名>', '<五期定点医疗机构编码>'); -- 五期医保
```

| 字段         | 说明                                                          | 示例值         |
| ------------ | ------------------------------------------------------------- | -------------- |
| `ins_id`   | 保险系统 ID，对应`insur.ins_system` 中 `sno=11/12` 的记录 | 见第三章       |
| `org_id`   | HIS 机构 ID                                                   | `1`          |
| `org_name` | 定点机构名称（医保中心备案名）                                | `XX 医院`    |
| `ins_code` | 定点医疗机构编码（医保中心分配）                              | 由医保中心提供 |

> **注意**：`ins_code` 国家版和五期版**通常不同**，必须分别向国家医保中心和上海五期医保中心索取。

## 五、项目对码

**表**：insur.ins_item_vs
**报错**：所有费用项目返回 `is_insure_item=0, special_mark=自费`
**触发时机**：`ItemMarking` 返回结果，门诊/住院结算费用明细上传
**根因**：HIS 院内费用项目未与医保目录建立对照关系

🚨 通过 HIS 医保工具菜单 → 项目对码，逐项建立 `fee_item_id → ins_item_code` 对照关系。

> 对码完成后，还需确认 `insur.ins_item.country_unified_code` 字段有值(见第六章)。

## 六、国家统一编码

**表**：insur.ins_item
**报错**：`下列项目：[xxx] 缺少国家码！请与本院相关部门联系进行补充。`
**触发时机**：门诊/住院预结算，费用明细上传校验阶段
**根因**：`ins_item.country_unified_code` 字段为空

🚨 通过项目对码工具的对照工具栏导入医保目录，系统会自动写入该字段。若无法联调，可临时 UPDATE：

> 执行域：**fee**

```sql
UPDATE insur.ins_item
SET country_unified_code = '<国家统一编码>'
WHERE ins_item_code = '<医保项目编码>';
```

## 七、医保配置信息

**表**：insur.insure_config
**报错**：`未查询到当前机构的国家医保配置信息，请联系管理员！`
**触发时机**：HIS 客户端启动时调用 `InitInsure` 初始化医保插件
**根因**：`insur.insure_config` 表中缺少当前机构的国家医保配置记录

🚨 每个启用国家医保的机构必须有一条配置记录，包含医保交易地址（url）、行政区划等关键参数。缺少此配置，医保插件初始化将直接失败。

> 执行域：**fee**

```sql
INSERT INTO insur.insure_config (ins_id, org_id, xzqh, url, medinstype, medinslv, znjgEnabled, admvs_area)
VALUES ('5388135717170938973', '1', '<行政区划编码>', '<医保交易URL>', '<机构类型>', '<机构等级>', '0', '<医保区划代码>');
```

| 字段            | 说明                                                               | 示例值                  |
| --------------- | ------------------------------------------------------------------ | ----------------------- |
| `ins_id`      | 国家医保保险系统 ID，对应`insur.ins_system` 中 `sno=12` 的记录 | `5388135717170938973` |
| `org_id`      | HIS 机构 ID                                                        | `1`                   |
| `xzqh`        | 就医地行政区划编码（6 位）                                         | `310000`              |
| `url`         | 国家医保交易地址（CSB HTTP 接口地址）                              | 由医保中心提供          |
| `medinstype`  | 医疗服务机构类型                                                   | `1`                   |
| `medinslv`    | 医疗机构等级                                                       | `3`                   |
| `znjgEnabled` | 智能监管启用标志（`0`=关闭，`1`=启用）                         | `0`                   |
| `admvs_area`  | 医保区划代码（与`xzqh` 通常一致，用于拼接对账唯一键）            | `310000`              |

> **注意**：五期通道（sno=11）走 `SendRcv4.dll` 直连前置机，不走 HTTP，因此**无需**为五期 ins_id 配置 URL。

## 八、科室对照

**表**：insur.ins_standard_dept、insur.ins_standard_dept_vs、insur.ins_standard_dept_sh、insur.ins_standard_dept_vs_sh
**报错**：`下列科室：[xxx] 未对照！`
**触发时机**：门诊/住院预结算，费用明细上传校验阶段（`handletype != "3"` 时）
**根因**：本地科室未与国家标准科室/上海五期标准科室建立对照

🚨 通过 HIS 医保工具完成，无需手动 SQL：

- **国家版科别对照**（function_no=1013）：左侧选中本地科室 → 双击右侧树节点 → 完成对照
- **五期版科别对照**（function_no=1012）：同样操作，走五期标准科室

> 工具界面支持直接新增标准科室节点（填写名称+编码，选择上级），无需提前 INSERT 字典表。详见第十五章。

若无法使用工具，可手动 INSERT（不推荐）：

> 执行域：**fee**

```sql
INSERT INTO insur.ins_standard_dept (id, standard_code, standard_name)
VALUES (gen_random_uuid()::varchar, '<编码>', '<科室名>');

INSERT INTO insur.ins_standard_dept_sh (id, standard_code, standard_name)
VALUES (gen_random_uuid()::varchar, '<编码>', '<科室名>');

INSERT INTO insur.ins_standard_dept_vs (local_dept_id, standard_dept_id, org_id)
SELECT '<本地科室id>', id, '1' FROM insur.ins_standard_dept
WHERE standard_code = '<编码>';

INSERT INTO insur.ins_standard_dept_vs_sh (local_dept_id, standard_dept_id, org_id)
SELECT '<本地科室id>', id, '1' FROM insur.ins_standard_dept_sh
WHERE standard_code = '<编码>';
```

## 九、医护人员编码

**表**：qw_base.b_staff
**报错**：`下列医护人员：[xxx] 未对码！请与本院相关部门联系进行医保对码。`
**触发时机**：门诊/住院预结算，费用明细上传校验阶段
**根因**：`b_staff.healthcare_code` 为空。代码直接取该字段作为开单医生国家编码（`PlacerCode`），上传费用明细时校验不通过。

🚨 先查出缺失医保编码的医生，再逐人补充 `healthcare_code`（该编码由卫健委统一分配，格式通常为 `D` 开头），可在人员管理中直接添加，或者使用 SQL 处理：

> 执行域：**patient**

```sql
-- 1. 查询所有医生性质且缺少国家编码的人员
SELECT id, code, name, healthcare_code
FROM qw_base.b_staff
WHERE prop LIKE '%A%'
  AND (healthcare_code IS NULL OR healthcare_code = '');

-- 2. 逐人补充国家编码
UPDATE qw_base.b_staff
SET healthcare_code = '<国家医师编码>'
WHERE id = '<人员ID>';
```

## 十、结算方式

**表**：qw_base.bhis_balance_mode（HIS 费用管理系统配置，非 SQL）
**报错**：`医保返回的结算方式【xxx】不在【结算方式管理】中，请检查是否设置本机构适用或结算方式是否为医保性质！`
**触发时机**：门诊/住院结算，`CheckBalanceWay` 校验阶段
**根因**：HIS 结算方式管理中缺少医保性质的结算方式

🚨 在 HIS 费用管理系统 → 结算方式管理中配置以下三条（性质=医保，勾选适用本机构）：

| 名称         | 性质           | 触发条件                          |
| ------------ | -------------- | --------------------------------- |
| `个人账户` | 4-医保各类统筹 | 个人账户各段支付之和 > 0          |
| `优惠减免` | 4-医保各类统筹 | 现金自付各段之和 > 0（SH01 通道） |
| `医保基金` | 4-医保各类统筹 | 统筹+附加支付之和 > 0             |

⚠️ SI11 通道的现金支付段 `balance_name` 写死为 `"现金"`，而 SH01 通道写的是 `"`。两者不一致，待确认后统一修复。

## 十一、疾病类型字典

**表**：insur.ins_disease_type
**报错**：慢病/特殊病登记、传染病登记、病种结算窗口提示"未查询到病种字典"或类似空结果
**触发时机**：调用慢病登记（如 `2401`）、病种结算（如 `2207A`）、传染病上报等接口时，由 HIS 弹出的"病种选择"窗口触发（`DataHelper.cs:354`）
**根因**：`insur.ins_disease_type` 表无对应 `ins_id` 和 `disease_type` 的字典数据

⚠️ **非门诊普通结算的硬阻塞项**，但启用慢病/病种相关接口前必须导入。`disease_type` 按医保规范分类（慢病/急性传染病/慢性传染病/特殊病等，具体编码见医保中心下发字典）。

> 执行域：**fee**

```sql
-- 数据来自医保中心下发的标准疾病分类字典，由医保实施人员导入
INSERT INTO insur.ins_disease_type (ins_id, disease_type, code, name, py_code)
VALUES ('5388135717170938973', '<分类码>', '<医保疾病编码>', '<疾病名称>', '<拼音码>');
```

> 若暂不启用慢病/特殊病结算，可跳过本章节，待启用前补齐。

## 十二、日对账表结构

**表**：insur.daily_reconcile_main、insur.daily_reconcile_detail
**用途**：结算对账工具依赖这两张表存储对账结果（日对账状态、险种明细、账平/账不平标记）。
**说明**：⚠️ 非核心结算阻塞项，但若未建表，结算对账工具（function_no=1020）将无法使用。

> 执行域：**fee**。DDL 已包含在第二章的对账表脚本中；表结构详情见 `docs/日对账记录表结构.sql`、`docs/日对账记录查询功能说明.md`。

**使用方式**：

1. 打开结算对账工具 → 执行对总账操作，系统自动创建对账主记录并逐险种/清算类别保存明细
2. 点击"对账查询"可查看历史记录，默认显示当月已对账数据，支持按日期、状态、险种、对账结果筛选
3. 双击某条记录查看该日明细，账不平项红色标识

**注意事项**：

- 只有通过系统执行的对账才会保存记录，历史数据不会自动回填
- 保存的是对账时刻的数据快照，后续数据变更不影响已保存记录
- 已建索引（日期、机构、状态），查询时建议指定日期范围避免全表扫描

## 十三、HIS 基础数据排错指南

> 以下数据**不属于医保插件部署范围**，而是 HIS 装机时由 HIS 实施团队建立的基础字典/基础字段。
> 列在此处的目的是：**联调期看到对应报错时，能快速定位是 HIS 基础数据问题，而非医保配置问题**，避免方向走偏延误进度。

### 13.1 人员类别字典缺失

**字段**：qw_base.b_pt_type
**代码位置**：`DataHelper.cs:305` —— 按 `name = @instypename` 查 `id`
**症状**：医保读卡 / 登记 / 参保类型切换接口报"人员类别未配置"或返回空 `id`
**根因**：HIS 基础字典 `qw_base.b_pt_type` 缺少医保对应的人员类别记录（如"职工医保"、"居民医保"等）

⚠️ **补救方向**：

1. 不要在医保插件这边改代码或塞数据
2. 联系 HIS 实施团队，在 HIS 基础数据管理 → 人员类别管理界面，补齐医保相关人员类别（名称需与医保插件传入的 `instypename` 完全一致）
3. 补完后无需重启医保插件，下次接口调用即可生效

### 13.2 机构属性字段为空

**字段**：qw_base.b_org.property
**代码位置**：`Cls_SHGBYB.InitInsure:99` —— `orgProperty = dt1.Rows[0]["property"].ToString()`
**症状**：`orgProperty` 取到空字符串，导致依赖机构属性的分支逻辑（综合 / 专科 / 中医）走错路径；表现为某些接口偶发性失败或返回与机构性质不符的错误
**根因**：HIS 装机时未填写 `qw_base.b_org.property`（医疗机构属性：综合 / 专科 / 中医等，编码按当地医保规范）

⚠️ **补救方向**：

1. 联系 HIS 实施团队，在 HIS 机构管理界面填写"机构属性"字段
2. 紧急情况下由数据库管理员直接 UPDATE：
   ```sql
   -- 执行域：与 HIS 主库一致
   UPDATE qw_base.b_org SET property = '<属性编码>' WHERE id = '1';
   ```
3. 修改后需重启 HIS 客户端，重新走一遍 `InitInsure` 才能加载新的 `orgProperty`

### 13.3 排错判断原则

看到"医保接口异常"但插件配置（第二~九章）已确认无误时，按 `InitInsure` 调用链反查 HIS 基础数据：

| 检查项                                     | 验证 SQL                                                             |
| ------------------------------------------ | -------------------------------------------------------------------- |
| `qw_base.b_org.property` 非空            | `SELECT property FROM qw_base.b_org WHERE id = '1';`               |
| `qw_base.b_staff.healthcare_code` 已对码 | 见第九章 SQL                                                         |
| `qw_base.b_pt_type` 有医保类别记录       | `SELECT id, name FROM qw_base.b_pt_type WHERE name LIKE '%医保%';` |

> **重要**：此章节是"排错索引"，不是"数据建立指南"。医保实施人员遇到这些报错时，应立即转交 HIS 实施团队处理，不要在医保插件这边硬塞数据或改代码绕过。

## 十四、InitInsure 卡点对照表

> 联调期看到 `InitInsure` 报错时，按以下表格反向定位缺失配置。

### 15.2 部署顺序与操作步骤

#### 第一步：导入医保目录 + 项目对码

1. 通过 HIS 医保菜单打开 **项目对码** 工具
2. 使用工具栏中的对照功能导入医保目录（药品、诊疗、耗材、诊断等）
3. 目录导入后，`ins_item` 表的 `country_unified_code` 会自动写入
4. 将本院收费项目逐项与医保目录建立对照关系
5. 对码完成后，所有费用项目的 `ins_item_vs` 表中应有对照记录

> 验证方法：在门诊医生站开一条医嘱，调用 `ItemMarking` 打标，确认返回的 `is_insure_item=1`。

#### 第二步：科室对照（国家+五期各做一次）

1. 打开 **国家版科别对照**：
   - 在"未对码"页签选中左侧一条本地科室
   - 双击右侧标准科室树中对应的科室节点 → 弹窗"对照成功"
   - 重复直到所有科室对照完毕
   - 如果标准科室树里找不到目标科室：在右侧上方输入面板填写**名称**和**编码**，选择上级（可选），点击"添加"，然后继续对码
2. 打开 **五期版科别对照**，重复同样操作
3. 切换到"已对码"页签，检查对照结果；双击误对照的行可取消

#### 第三步：补充医生人员医保编码

- 在 HIS 人员管理中为所有医生性质的员工填写 `healthcare_code`（人员医保编码）
- 或执行第九章 SQL 批量查询缺失项，再逐人补充

#### 第四步：联调验证

1. 完成一笔五期门诊挂号 → 打开 **五期医保结算信息查询**，输入查询条件，确认能查到该笔记录
2. 如结算后发现金额不对，在查询结果中右键 → **医保平台退费**，输入凭证信息完成退款
3. 完成一笔国家医保门诊结算 → 打开 **结算对账**，选择当天日期，点击对账，确认两边数据一致
4. 如需撤销某笔费用明细上传，打开 **国家医保撤销工具**，填入就诊ID、收费批次号（填 `0000` 撤销全部未结算明细）、人员编号

### 15.4 工具菜单配置

医保工具通过 HIS 宿主的**统一事件管理**配置菜单入口。每个工具对应一个 `function_no`，配置时填入以下 JSON 参数：

```
function_no: 1012（五期科别对照）/ 1013（国家科别对照）/ ...（见 15.1 表格序号）
ins_id:      保险系统ID（总线=1，国家=2，五期=3；菜单级的 ins_id 会传给对应通道）
org_id:      机构ID
operator_id: 操作员ID
operator_name: 操作员姓名
dept_id:     科室ID
```

> **注意**：`1015` 已废弃，不要配置。五期退费请使用 `1016` 五期医保结算信息查询内的右键退费功能。

### 15.5 启用医保参数设置工具（功能号 1028）

#### 用途

通过界面维护 `insur.ins_initial`（KV 表）里的医保参数：

- 国家医保（sno=12）：接口地址 / 就医地行政区划 / 医疗服务机构类型 / 医疗机构等级 / 启用智能监管
- 上海五期（sno=11）：参保地医保区划 / 就医地医保区划

窗体按打开时传入的 `ins_id` 自动识别 sno，只显示对应分组；内置"连接测试"（国家走 9001 签到 / 五期走 SI91 交易查询）和"读卡测试"（五期 S000）。

#### 启用步骤

**1. 程序集层**：`Cls_SHGBYB.InterfaceTools` 已添加 `case "1028"` 分支并指向 `Tools/Frm医保参数设置`，重新构建 `zlchs.SH.GJBYB.insure.dll` 并替换到 HIS 客户端 `Plugins/` 目录即可。

**2. 数据库层**：在 `insur.ins_tools` 插入两条记录——国家、五期各一条入口。**`no_init` 字段必须设为 `'1'` 跳过 `InitInsure`**（医保参数设置工具本身就是用来填初始化所需参数的，否则形成循环依赖）。

```sql
-- 国家医保参数设置入口
INSERT INTO insur.ins_tools(id, ins_id, name, sno, function_no, no_init)
VALUES (
    <雪花 id>,
    (SELECT id FROM insur.ins_system WHERE sno = 12),
    '国家医保参数设置',
    12,
    '1028',
    '1'
);

-- 上海五期医保参数设置入口
INSERT INTO insur.ins_tools(id, ins_id, name, sno, function_no, no_init)
VALUES (
    <雪花 id>,
    (SELECT id FROM insur.ins_system WHERE sno = 11),
    '上海五期医保参数设置',
    11,
    '1028',
    '1'
);
```

#### 验证流程

1. HIS 客户端重启，打开"保险相关工具"菜单
2. 列表能看到两行新增条目
3. 双击其一 → 弹窗自动定位到对应分组（国家或五期）
4. 填入参数 → 点保存 → 在 `insur.ins_initial` 表用 `select * from insur.ins_initial where ins_id = '<对应 ins_id>'` 验证 KV 行已写入

#### 数据流（修复后）

`DataHelper.GetInsureConfig` 已改为从 `insur.ins_initial` 用聚合枢轴查 5 个参数（`接口地址 / 就医地行政区划 / 医疗服务机构类型 / 医疗机构等级 / 启用智能监管`）：

```
本工具填值（保存）→ insur.ins_initial（KV 行）
                          ↑
                  InitInsure → GetInsureConfig 读取（pivot 成 5 列单行 DataTable）
                          ↓
              BusinessHelper.url / mdtrtareaAdmvs / medinsType / medinsLv / znjgEnabled
                          ↓
                     国家医保业务（YBBusiness 调 CSB）
```

`url` 列为空视为未配置——`GetInsureConfig` 内部清空 Rows，触发 `InitInsure` 报"未查询到当前机构的国家医保配置信息"，提示用户先来本工具填值。

#### ⚠️ 首次启用顺序（鸡生蛋问题）

**InitInsure 通过的前提是 ins_initial 已有数据；ins_initial 数据靠本工具填——这是循环依赖**。打破方法是用 `no_init='1'` 让工具菜单第一次跳过初始化：

1. 按 §15.5 SQL 插入 `ins_tools` 记录时，**`no_init='1'` 字段必填**
2. 工具菜单第一次打开本工具 → `Frm保险相关工具.cs` 第 276 行判断 `no_init=='1'` 跳过 InitInsure → 窗体正常弹出
3. 在窗体里填齐 5 个参数 → 保存 → `ins_initial` 落数据
4. 之后正式业务路径（门诊结算等）调 InitInsure 即可正常读到配置
