# 部署包目录结构

> 著作权人：Keiskei
> 本文档面向**现场实施人员**，描述插件部署到 HIS 宿主进程目录的完整目录结构与部署步骤。

---

## 一、完整目录结构

```
<HIS 宿主进程目录>/                              ← 例：D:\Program Files\CPAPI\CPAPIClient
├── CPAPI.Client.exe                            ← 宿主主程序（HIS 自带）
├── Plugins.WebInsurance/                       ← 插件目录（本插件部署核心）
│   ├── Plugins.WebInsurance.dll                ← 宿主初始文件
│   ├── version.json                            ← 宿主初始文件
│   ├── zlchs.SH.GJBYB.insure.dll               ← 🚨 本插件主 DLL
│   ├── Castle.Core.dll                         ← 依赖（DBLoggingInterceptor AOP）
│   ├── Newtonsoft.Json.dll                     ← 依赖（JSON 序列化，防版本不一致）
│   └── shLibs/                                 ← 🚨 项目上提供 3 个本地 DLL（仅五期通道）
│       ├── SendRcv4.dll                        上海五期前置机通讯 DLL
│       ├── SSCardDriver.dll                    读卡器驱动（SendRcv4 运行时依赖）
│       └── SSSE32.dll                          SSCardDriver 依赖
└── InsureLog/                                  ← 运行期自动生成（插件日志）
    └── YYYYMMDD.log
```

### 2.2 项目上提供（部署包不含，必须现场补 3 个 DLL，仅五期通道需要）

| 文件                   | 来源                              | 部署位置                         |

## 四、部署顺序

```
1. 解压部署包到任意临时目录

2. 把部署包内 Plugins.WebInsurance\ 下的 5 个文件
   复制到目标 HIS 宿主的 Plugins.WebInsurance\ 目录下
   例如: D:\Program Files\CPAPI\CPAPIClient\Plugins.WebInsurance\
   - Plugins.WebInsurance.dll / version.json 如目标已有同版本可覆盖

3. 在目标 HIS 宿主的 Plugins.WebInsurance\shLibs\ 下
   放入项目上提供的 3 个本地 DLL（仅五期通道 sno=11 需要）
   - SendRcv4.dll / SSCardDriver.dll / SSSE32.dll
   - shLibs\ 目录不存在则手工创建

4. 数据库前置准备（fee 域，PostgreSQL）
   执行 insur_补表_创建脚本.sql（含 27 张表，日对账两张表已包含其中）
   再按 docs\医院部署前置配置清单.pdf 完成数据配置（保险系统映射、医院对照、配置信息、项目对码、科室对照、医护人员编码等）

5. 跑自检脚本验证前置配置
   psql -d <fee 域库名> -f docs\deploy_healthcheck.sql
   所有 ❌ 项必须修复；⚠️ 项按业务场景酌情处理

6. 启动 HIS 客户端验证
   - 检查 <宿主目录>\InsureLog\YYYYMMDD.log 是否生成
   - 触发一次医保登录（InitInsure）
   - 日志末尾应打印 "【初始化结束】"
```

## 五、部署后验证

```
1. 启动 HIS 客户端
   └── InsureLog\YYYYMMDD.log 是否生成
       ├── 是 → ✅ 插件已被加载
       └── 否 → 查看 HIS 主程序错误日志，确认 Plugins.WebInsurance\
                  下 5 个文件齐全且未被 SmartScreen / 杀软拦截

2. 跑 deploy_healthcheck.sql
   └── 所有 ❌ 必须修复（详见医院部署前置配置清单.pdf）

3. 触发一次 InitInsure（医保登录或患者读卡）
   └── 看日志末尾是否打印 "【初始化结束】"
       ├── 是 → ✅ 网络通、配置全
       └── 否 → 对照医保错误码处理手册.pdf 反查

4. 试一次 ItemMarking（门诊医生站开一条医嘱）
   └── 看打标返回 is_insure_item / special_mark 是否正常
```

## 六、常见部署问题

### 6.1 DllNotFoundException: shLibs\SendRcv4.dll

**症状**：上海五期通道任何接口报"无法加载 DLL shLibs\SendRcv4.dll"。

**根因**：`Plugins.WebInsurance\shLibs\` 目录未创建，或 `SendRcv4.dll` 缺失。

**排查**：

1. 确认 `<宿主目录>\Plugins.WebInsurance\shLibs\SendRcv4.dll` 存在
2. 验证 DLL 完整性：`dir Plugins.WebInsurance\shLibs\SendRcv4.dll` 应看到文件且大小 > 0
3. 检查 DLL 位数：宿主进程为 32 位（x86）时，`SendRcv4.dll` 必须是 x86 版本

### 6.2 TypeLoadException: Castle.Core / Newtonsoft.Json

**症状**：HIS 启动时弹出"无法加载类型 Castle.DynamicProxy..."或类似异常。

**根因**：`Plugins.WebInsurance/` 下缺少 `Castle.Core.dll` 或 `Newtonsoft.Json.dll`。

**排查**：确认部署包内 5 个文件全部复制到目标 `Plugins.WebInsurance/` 下。

### 6.3 国家医保 CSB 调用报 9000 签名超时

**症状**：所有国家医保接口返回签名相关错误。

**根因**：服务器系统时间与医保中心服务器时间偏差 > 30 秒。

**排查**：

1. 同步前置机系统时间至 NTP 标准时间
2. 时区设置应为 `(UTC+08:00) 北京`

## 七、回滚

新版本部署后出现严重问题，回滚步骤：

1. 备份当前 `Plugins.WebInsurance\zlchs.SH.GJBYB.insure.dll` 为 `*.dll.broken`
2. 把上一个稳定版本的 DLL 复制回 `Plugins.WebInsurance\`
3. **不需要**回滚数据库——本次 DDL 都是 `CREATE IF NOT EXISTS`，多余的表不影响旧版本运行

> `Plugins.WebInsurance\shLibs\` 中的 3 个本地 DLL 跨版本兼容，一般不需要回滚。
