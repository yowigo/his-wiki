## 1. 改造背景

按照医保规范，定点医疗机构的结算项目原则上都应完成医保对码后方可上传结算。但对于盈利性医疗机构（如希玛眼科），大量项目不纳入医保报销范围、不走医保对码流程是普遍存在的业务常态。

当前做法：费用信息上传时一旦检测到未对码项目，直接报错中断，要求操作员联系相关部门完成对码后重新结算。这在公立医院场景下合理，但在希玛眼科等盈利性机构中会导致大量正常自费项目无法完成结算流程。

需求：将医保项目和自费项目分开结算。费用信息上传时若发现未对码项目，给出弹窗两个选择：

1. **对码后重新结算** — 当前做法，直接 return
2. **继续结算** — 过滤掉没有医保编码的明细，不上传国家平台，同时跳过医保误差判断

**业务原理**：HIS 在结算时会汇总所有结算方式（个人账户、医保基金、现金等）的返还金额，患者现金支付部分为总金额扣减各医保结算方式返还后的差额。未对码项目不上传后，医保平台仅对已上传项目计算返还，被过滤项目对应的费用自然落入差额中由患者自费承担，不需要额外处理。

## 2. 改造范围

### 2.1 弹窗改造（3 处）

将"医保未对码"校验从直接报错改为二选一弹窗。

> ℹ️ "医保未对码"的判定条件：`InsMedicalCode`（门诊）/ `InsItemCode`（住院）为空，且 `LocalFeeType != "自费"`。

| #  | 方法                                          | 行号      | 场景                    | 校验字段           |
| -- | --------------------------------------------- | --------- | ----------------------- | ------------------ |
| A1 | `ClinicPreSwap`                             | 2464~2482 | 门诊预结算（国家+五期） | `InsMedicalCode` |
| A2 | `ProcessNationalInpatientPreSettlement`     | 5867~5887 | 国家住院预结算          | `InsItemCode`    |
| A3 | `ProcessFifthVersionInpatientPreSettlement` | 6467~6485 | 五期住院预结算          | `InsItemCode`    |

> ℹ️ 以下校验**不在本次范围**，保持现状：MaterialCountryCode（材料国家码）、CountryCode（非材料国家码）、OutPayRate（五期自付比例）、科别对照、PlacerCode（医生编码）。

### 2.2 误差判断跳过（6 处）

当用户选择"继续结算"后，设置标志位 `SkipInsureErrorCheck`，后续误差判断（`> 0.1 元` 硬阻塞）检查此标志位，若为 true 则仅记日志不阻塞。

| #  | 方法                                       | 行号      | 场景               | 备注                                   |
| -- | ------------------------------------------ | --------- | ------------------ | -------------------------------------- |
| B1 | `ProcessSI11Charge`                      | 2006~2014 | 五期门诊 SI11 试算 | `actual_charge` vs `totalexpense`  |
| B2 | `ProcessNationalPreSettlement`           | 3061~3078 | 国家门诊预结算     | `actual_charge` vs `medfee_sumamt` |
| B3 | `ProcessNationalInsuranceSettlement`     | 3459~3483 | 国家门诊正式结算   | 含撤销 2208 逻辑，跳过时一并跳过       |
| B4 | `ProcessNationalInpatientPreSettlement`  | 6375~6386 | 国家住院预结算     | `actual_charge` vs `medfee_sumamt` |
| B5 | `ProcessNationalInpatientSettlement`     | 7280~7293 | 国家住院正式结算   | 含撤销 2305 逻辑，跳过时一并跳过       |
| B6 | `ProcessFifthVersionInpatientSettlement` | 7647~7657 | 五期住院正式结算   | `actual_charge` vs `totalexpense`  |

### 2.3 新增基础设施

| 项           | 位置                  | 说明                                                                                                                   |
| ------------ | --------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 类级标志字段 | `Cls_SHGBYB` 类顶部 | `private static bool SkipInsureErrorCheck = false;` 跨预结算→正式结算保持                                           |
| 标志重置点   | 结算链路入口方法起始  | `ClinicPreSwap` / `ClinicSwap` / `WipeoffMoney` / `SettleSwap` + `InitInsure` 兜底，国家+五期均经这 4 个入口 |

## 3. 改造逻辑（伪代码）

### 3.1 A1~A3：未对码弹窗

```
if (未对码项目.Count > 0)
{
    收集未对码项列表 → undmlist（去重）
    写日志："【费用明细上传-未对码项目】{undmlist}"

    弹窗消息 = $"下列项目未进行医保对码：\n{undmlist}\n\n
                请选择处理方式：\n
                【是(Y)】对码后重新结算\n
                【否(N)】继续结算（过滤未对码项目，自费处理）"

    if (用户选择"是")  // 对码后重新结算
    {
        result["code"] = "0"
        result["message"] = msg
        return                              // ← 同现有行为
    }
    else  // 继续结算
    {
        日志："【费用明细上传-过滤未对码项目继续结算】过滤 {N} 条未对码明细"
        feeList = feeList.Where(有医保编码).ToList()   // 过滤
        SkipInsureErrorCheck = true                   // 设标志
        // 继续往下走
    }
}
```

## 4. 详细影响分析

### 4.1 费用数据流

```
总金额（HIS）= 医保各结算方式返还（个人账户 + 医保基金 + 医保钱包等）+ 患者现金支付
                         ↑                                      ↑
                 医保平台按上传明细计算                   差额自动归入
                 (仅包含已对码项目)                  (被过滤项目→自费承担)
```

### 4.2 `actual_charge` 参数使用点排查

| 方法                                       | 使用方式                                | 过滤后是否受影响 |
| ------------------------------------------ | --------------------------------------- | :--------------: |
| `ProcessSI11Charge`                      | 仅误差比较 + 保存`insure_error_money` | ❌ 否（已跳过） |
| `ProcessNationalPreSettlement`           | 仅误差比较                              |      ❌ 否      |
| `ProcessNationalInsuranceSettlement`     | 仅误差比较 + 撤销                       |      ❌ 否      |
| `ProcessNationalInpatientPreSettlement`  | 仅误差比较                              |      ❌ 否      |
| `ProcessNationalInpatientSettlement`     | 仅误差比较 + 撤销                       |      ❌ 否      |
| `ProcessFifthVersionInpatientSettlement` | 仅误差比较                              |      ❌ 否      |
| 费用明细上传请求体（2204/SN01）            | `zfy` 从 `feeList` 累加             | ✅ 已过滤，正确 |

> ✅ 结论：`actual_charge` 在整个流程中**仅用于误差比较**，不参与上传请求体的费用总额计算。请求体中的 `medfee_sumamt`（国家）和 `bcmxylfyze`（五期）均由过滤后的 `feeList` 实时累加得到，金额正确。

### 4.3 跨请求标志位生命周期

```
门诊场景（国家）:
  ClinicPreSwap(预结算)           → 设标志 → 返回
  ProcessNationalInsuranceSettlement(正式结算) → 检查标志 → 跳过误差

住院场景:
  ProcessXxxInpatientPreSettlement(预结算) → 设标志 → 返回
  ProcessXxxInpatientSettlement(正式结算)   → 检查标志 → 跳过误差
```

标志位在 `Cls_SHGBYB` 类级别（`static`），DLL 生命周期内有效。每个 public 入口方法起始处重置为 `false`。

### 4.4 不影响项

| 项                                     | 说明                                   |
| -------------------------------------- | -------------------------------------- |
| 自费项目（`LocalFeeType == "自费"`） | 原本就被排除，不动                     |
| 材料国家码校验                         | 保持现状，直接报错                     |
| 非材料国家码校验                       | 保持现状，直接报错                     |
| 五期自付比例校验                       | 保持现状，直接报错                     |
| 科别对照校验                           | 保持现状，直接报错                     |
| 医生编码校验                           | 保持现状，直接报错                     |
| 正式结算撤销逻辑                       | 仅在误差跳过时同步跳过，不影响正常撤销 |
