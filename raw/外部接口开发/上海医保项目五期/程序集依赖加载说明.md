# 动态库依赖程序集自动加载方案

## 问题背景

主程序通过以下方式反射加载本 DLL:
```csharp
targetAssembly = Assembly.Load(File.ReadAllBytes(Path.Combine(path, assemblyName + ".dll")));
foreach (Type clsName in targetAssembly.GetTypes()) { ... }
```

这种加载方式会导致:
1. **程序集无物理路径**:使用 `Assembly.Load(byte[])` 加载的程序集 `Location` 属性为空
2. **依赖无法自动定位**:依赖的 DLL(如 NPOI、SharpZipLib 等)找不到,抛出 `TypeLoadException`
3. **无法修改主程序**:无法在主程序中添加配置或代码

## 解决方案

### 核心机制

在 DLL 内部实现 `AssemblyResolve` 事件处理,在程序集加载时自动注册,从指定子目录加载依赖。

### 实现文件

1. **AssemblyResolver.cs** - 程序集解析器
   - 静态构造函数自动注册 `AppDomain.AssemblyResolve` 事件
   - 支持从多个路径获取 DLL 目录(包括 `Assembly.Load(byte[])` 场景)
   - 从指定子目录自动加载依赖

2. **Cls_SHGBYB.cs** - 主接口类
   - 静态构造函数触发 `ModuleInitializer.EnsureInitialized()`
   - 确保在任何方法调用前完成初始化

3. **Properties/AssemblyInfo.cs** - 程序集信息
   - 添加 `AssemblyInitializer` 强制在程序集加载时初始化

### 搜索优先级

程序集解析器按以下顺序搜索依赖:
1. `libs/` 子目录 ⭐ **推荐**
2. `dependencies/` 子目录
3. `bin/` 子目录
4. DLL 所在目录(最后)

### DLL 目录获取策略

针对 `Assembly.Load(byte[])` 加载方式,实现了多重定位策略:

```csharp
1. RequestingAssembly.Location  ← 最关键,从请求程序集获取
2. Assembly.Location             ← 标准方式
3. 已加载程序集查找              ← 遍历 AppDomain
4. Assembly.CodeBase             ← 备用方案
```

## 使用说明

### 1. 编译项目

正常编译项目,无需特殊配置。

### 2. 部署文件

**方案A: 手动部署**
1. 将编译后的所有依赖 DLL 复制到 `libs` 子目录
2. 确保 `zlchs.SH.GJBYB.insure.dll` 与 `libs/` 在同一目录

**方案B: 使用后期生成事件** (推荐)

在项目文件 `.csproj` 中添加:
```xml
<Target Name="CopyDependenciesToLibs" AfterTargets="Build">
  <ItemGroup>
    <DependencyDlls Include="$(OutputPath)*.dll" 
                    Exclude="$(OutputPath)$(AssemblyName).dll;
                             $(OutputPath)zlchs.*.dll;
                             $(OutputPath)ZLSoft.*.dll;
                             $(OutputPath)Oracle.*.dll" />
  </ItemGroup>
  <MakeDir Directories="$(OutputPath)libs" />
  <Copy SourceFiles="@(DependencyDlls)" 
        DestinationFolder="$(OutputPath)libs" 
        SkipUnchangedFiles="true" />
</Target>
```

### 3. 日志查看

程序集加载日志会记录在:
```
InsureLog/年月日.log
```

日志内容包括:
- ✓ 成功加载的程序集路径
- ✗ 加载失败的程序集及错误信息
- DLL 目录定位过程
- 程序集搜索路径

### 4. 故障排查

**问题**: 仍然提示找不到程序集

**排查步骤**:

1. **检查日志文件**
   ```
   InsureLog/YYYYMMDD.log
   ```
   查看是否有 "尝试解析程序集" 的日志

2. **验证目录结构**
   ```cmd
   dir /s *.dll
   ```
   确认 libs 目录存在且包含依赖

3. **检查文件名**
   - 确保 DLL 文件名与程序集名称一致
   - 例如: `NPOI.OOXML.dll` 对应程序集名 `NPOI.OOXML`

4. **手动触发初始化** (调试用)
   
   在主程序加载后立即调用:
   ```csharp
   var initType = targetAssembly.GetType("zlchs.SH.GJBYB.insure.ModuleInitializer");
   initType?.GetMethod("EnsureInitialized")?.Invoke(null, null);
   ```

5. **使用 Fusion Log Viewer**
   
   微软官方工具,查看详细的程序集绑定日志:
   ```cmd
   fuslogvw.exe
   ```

## 技术细节

### 为什么静态构造函数可能不执行?

使用 `Assembly.Load(byte[])` 加载程序集时:
- 程序集被加载到内存,但没有关联文件路径
- 调用 `GetTypes()` 时会加载类型,但**不一定**触发静态构造函数
- 只有在实际**使用类型**时才触发静态构造函数

### 多重初始化机制

为确保万无一失,实现了三层初始化:

1. **AssemblyInitializer** (Properties/AssemblyInfo.cs)
   - 程序集级别,最早执行
   
2. **ModuleInitializer** (AssemblyResolver.cs)
   - 模块级别,次早执行
   
3. **Cls_SHGBYB 静态构造函数**
   - 类型级别,保底机制

### 为什么使用 RequestingAssembly?

```csharp
args.RequestingAssembly  // 请求加载依赖的程序集
```

当主程序通过 `Assembly.Load(byte[])` 加载我们的 DLL 后:
- 我们的 DLL 的 `Location` 为空
- 但当我们的代码尝试加载依赖(如 NPOI)时
- `RequestingAssembly` 指向我们的 DLL
- 即使是从字节数组加载的,也能通过已加载程序集列表找到路径

## 注意事项

1. **libs 目录必须与 DLL 同级**
   ```
   正确: D:\App\zlchs.SH.GJBYB.insure.dll
         D:\App\libs\NPOI.dll
   
   错误: D:\App\zlchs.SH.GJBYB.insure.dll
         D:\libs\NPOI.dll
   ```

2. **版本兼容性**
   - 确保依赖 DLL 版本与 App.config 中的 bindingRedirect 一致
   - 推荐使用与项目相同的 .NET Framework 版本

3. **性能考虑**
   - 程序集解析器只在找不到程序集时触发
   - 已加载的程序集不会重复加载
   - 目录路径会缓存,减少文件系统访问

4. **安全性**
   - 只从预定义的子目录加载程序集
   - 使用 `Assembly.LoadFrom` 而非 `Assembly.LoadFile`
   - 保持依赖程序集的强命名签名
