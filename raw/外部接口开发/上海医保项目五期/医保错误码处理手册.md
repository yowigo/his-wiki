# 医保错误码处理手册

> 著作权人：Keiskei
> 本手册针对**联调与日常运维**中医保接口返回的错误，按通道分类列出处置方向。
> 仅覆盖项目代码实际识别的错误类别和典型业务前置错误；完整错误码定义请查阅医保中心下发的接口规范 PDF（`docs/中心系统与定点医疗机构接口规范（第五版-完整版）.md`）。

---

## 符号说明

| 符号 | 含义 |
| ---- | ---- |
| 🚨 | 阻塞所有交易，必须先排除 |
| ⚠️ | 影响单笔业务，可重试或换通道 |
| ℹ️ | 信息性提示，无需处置 |

## 一、国家医保通道（CSB HTTP）

### 1.1 通用判定逻辑

国家通道是 CSB HTTP 协议，请求经签名后 POST 到医保中心。**关键判断**：

```
响应 JSON → infcode 字段
├── infcode = "0"  → 业务成功，主响应在 output 字段
└── infcode ≠ "0" → 失败，错误描述在 err_msg / warn_msg 字段
```

接口返回错误时，插件**直接把 `err_msg` 通过弹窗呈现给操作员**，因此现场看到的错误文案就是医保中心的原始描述。

---

### 1.2 通用业务错误（infcode ≠ "0"）

| 现象                                  | 排查方向                                                                                       |
| ------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 🚨 任意接口返回 `infcode ≠ "0"`     | 1. 看 `err_msg` 文案——多数情况下描述直接说明问题（如"参保人未参保"、"医师未备案"）           |
| 🚨 `err_msg` 含"签名"、"验签失败"  | 服务器时间不同步、CSB 签名证书过期或路径错误（见 §1.3）                                       |
| 🚨 `err_msg` 含"操作员"、"opter"   | 操作员未在医保中心备案，或 `b_staff.healthcare_code` 与医保中心备案号不匹配                    |
| ⚠️ `err_msg` 含"参保"、"未参保"   | 持卡人在医保中心查不到，常见于跨地区参保、刚转入未及时同步                                     |
| ⚠️ `err_msg` 含"目录"、"医保编码" | `country_unified_code` 缺失或与医保中心目录脱节（参考部署清单第五章，重新导入医保目录）        |
| ⚠️ `err_msg` 含"科室"             | 当前科室未对码或对码错误（参考部署清单第八章）                                                 |
| ⚠️ `err_msg` 含"违反"、"超限额"   | 业务规则限制：日限额 / 次限额 / 重复用药等，由医保中心规则引擎触发                             |

> **现场处置原则**：先看 `err_msg` 文字，多数情况下是**业务前置数据问题**（医师/科室/目录），而不是技术问题。先按部署清单"InitInsure 卡点对照表"和"HIS 基础数据排错指南"反查。

---

### 1.3 CSB 签名与时间相关错误

| 错误码 / 文案     | 含义                                          | 处置                                                                            |
| ----------------- | --------------------------------------------- | ------------------------------------------------------------------------------- |
| 🚨 `9000` 签名超时 | 客户端签名时间戳与医保中心服务器偏差 > 阈值   | 同步前置机系统时间至 NTP 标准时间，时区设为 `(UTC+08:00) 北京`                  |
| 🚨 验签失败       | CSB 公私钥不匹配，或签名内容被篡改            | 1. 联系医保中心确认本机构 CSB 密钥未过期<br/>2. 联系开发核查插件签名实现                       |
| 🚨 证书已过期     | CSB 接入证书过期                              | 联系医保中心更新证书                                                            |

---

### 1.4 网络与 HTTP 错误

国家通道走 HTTP，可能在到达医保中心**之前**就失败。这类错误**不带 infcode**，表现为接口直接抛异常。

| 现象                                            | 排查方向                                                                                |
| ----------------------------------------------- | --------------------------------------------------------------------------------------- |
| 🚨 `HttpRequestException` / 连接超时           | 1. ping `insure_config.url` 对应主机<br/>2. 防火墙是否放行 CSB 端口<br/>3. 代理配置正确性 |
| 🚨 `404 Not Found` / `405 Method Not Allowed` | `insure_config.url` 配置错误（参考部署清单第七章）                                      |
| 🚨 SSL/TLS 握手失败                            | 服务器未启用 TLS 1.2 或更高版本                                                         |

> 此类错误**不会**写入 `insur.ins_log`（数据库日志只记录已成功发出的请求），需要在 `InsureLog/YYYYMMDD.log` 文件日志中找异常堆栈。

---

### 1.5 签到流程错误（9001 / InitInsure）

`InitInsure` 末尾会调用医保中心的 `9001`（签到）接口。这是每天首次启动 HIS 时触发，失败会阻塞所有后续交易。

| 现象                       | 处置                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| 🚨 `签到失败！{output}`   | `output` 内有具体原因，按文字反查：<br/>- 操作员未备案 → 联系医保中心备案<br/>- IP/MAC 不匹配 → 看医保中心是否限制接入设备 |
| 🚨 `今天已签退`           | 业务上需次日重新签到，**不是配置问题**                                                                |
| ⚠️ 签到成功但后续交易失败 | 签到流水号未正确传递到后续接口，联系开发排查                                                          |

## 二、上海五期通道（SendRcv4.dll 本地调用）

### 2.1 通用判定逻辑

五期通道通过本地 DLL `shLibs\SendRcv4.dll` 调用前置机。**关键判断**：

```
响应 JSON → xxfhm 字段
├── xxfhm = "P001"  → 业务成功
└── xxfhm ≠ "P001"  → 失败
```

响应编码为 **GBK**，请求编码为 **UTF-8**，编码不一致会导致中文乱码。

> **五期通道日志不入数据库**：所有日志只在 `InsureLog/YYYYMMDD.log` 文件中。

---

### 2.2 通用业务错误（xxfhm ≠ "P001"）

| 现象                                 | 排查方向                                                       |
| ------------------------------------ | -------------------------------------------------------------- |
| 🚨 `xxfhm ≠ "P001"`               | 响应主体的中文描述就是错误原因，按文字直接定位                 |
| ⚠️ 响应中文乱码                    | 五期返回 GBK 编码，代码已处理；如果仍乱码检查 `.NET CodePage 936` 是否可用 |

---

### 2.3 五期 DLL 加载错误

| 错误码 / 现象                                | 处置                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| 🚨 `DllNotFoundException: shLibs\SendRcv4.dll` | `shLibs/` 目录未创建或 DLL 缺失（参考部署包目录结构 §6.2）                              |
| 🚨 `BadImageFormatException`                | DLL 位数与宿主进程不匹配——宿主 x86 必须用 x86 版本的 SendRcv4.dll                       |
| 🚨 `AccessViolationException`                | DLL 内部崩溃，通常是前置机服务未启动或被防火墙拦截。重启五期前置机服务                 |

---

### 2.4 前置机通讯错误

| 现象                       | 处置                                                                       |
| -------------------------- | -------------------------------------------------------------------------- |
| 🚨 调用 SendRcv4 后无响应或挂起 | 1. 前置机服务未启动 → 启动上海五期前置机服务<br/>2. 前置机 IP 改了 → 修改前置机配置文件 |
| 🚨 响应返回空字符串        | 前置机内部错误，看前置机日志（通常在前置机软件安装目录 `log/`）             |

## 三、读卡器错误（`HeaSecReadInfo.dll` / `NationECCode.dll`）

### 3.1 读卡器初始化失败

| 错误                                  | 处置                                                                |
| ------------------------------------- | ------------------------------------------------------------------- |
| 🚨 `DllNotFoundException: HeaSecReadInfo.dll` | `shLibs/` 缺读卡器 DLL（参考部署包目录结构 §2.2）                   |
| 🚨 读卡器无响应                      | 1. 检查 USB 连接<br/>2. 重装读卡器驱动<br/>3. 服务"卡读取服务" 已启动 |
| ⚠️ 读卡返回部分字段为空              | 卡损坏或读卡器接触不良，让患者重新插卡                              |

### 3.2 电子凭证错误（`NationECCode.dll`）

| 错误                       | 处置                                                            |
| -------------------------- | --------------------------------------------------------------- |
| 🚨 电子凭证解码失败       | 1. SDK 版本与医保中心不匹配 → 更新 `NationECCode.dll`<br/>2. 二维码已过期，重新生成 |
| ⚠️ 电子凭证读取空 / 部分字段为空 | 网络问题，电子凭证解码需要联网验证，检查前置机网络               |

## 四、业务前置错误（项目代码主动 ShowMsg）

以下错误**不是医保中心返回**，而是插件代码在调用医保前的本地校验失败。这类错误**指向部署前置数据问题**，全部通过 `BaseTools.ShowMsg("医保接口提示", ...)` 弹窗。

| 弹窗文案                                                       | 根因                                       | 修复章节                          |
| -------------------------------------------------------------- | ------------------------------------------ | --------------------------------- |
| 🚨 `获取保险系统映射配置失败！`                               | `insur.ins_system_mapping` 未配置          | 部署清单 第六章                   |
| 🚨 `获取国家医保保险系统信息失败！` / `获取五期医保保险系统信息失败！` | `insur.ins_system` 缺 sno=11/12 记录       | 部署清单 第六章                   |
| 🚨 `当前机构未维护「国家医保」/「上海五期医保」医院对照！`     | `insur.ins_org_vs` 缺当前机构记录          | 部署清单 第三章                   |
| 🚨 `未查询到当前机构的国家医保配置信息，请联系管理员！`       | `insur.insure_config` 缺当前机构国家通道配置 | 部署清单 第七章                   |
| 🚨 `下列项目：[xxx] 缺少国家码！`                             | `ins_item.country_unified_code` 为空       | 部署清单 第五章                   |
| 🚨 `下列科室：[xxx] 未对照！`                                 | `ins_standard_dept_vs*` 缺记录             | 部署清单 第八章                   |
| 🚨 `下列医护人员：[xxx] 未对码！`                             | `b_staff.healthcare_code` 为空             | 部署清单 第九章                   |
| 🚨 `医保返回的结算方式【xxx】不在【结算方式管理】中`          | HIS 结算方式管理缺医保性质                 | 部署清单 第十章                   |
| ℹ️ `今天已签退，请于第二天签到！`                            | 业务正常，非错误                           | ——                                |
| ⚠️ `五期退费请通过【五期医保结算信息查询】工具操作。`        | 走错入口，用对应工具                       | 部署清单 第十五章 工具总览        |

> **快速定位**：99% 的弹窗错误用部署清单 **第十四章 InitInsure 卡点对照表** 或 **第十三章 HIS 基础数据排错指南** 能直接对上。

## 五、日志查阅

### 5.1 数据库日志（仅国家通道）

```sql
-- 查最近 1 小时的国家医保接口调用
SELECT inf_time, infno, opter, result_status, fail_message
FROM insur.ins_log
WHERE inf_time > now() - interval '1 hour'
ORDER BY inf_time DESC
LIMIT 50;

-- 看特定交易的完整请求/响应
SELECT input, output FROM insur.ins_log WHERE msgid = '<报文ID>';
```

### 5.2 文件日志（两个通道都有）

```
<HIS 宿主目录>\InsureLog\YYYYMMDD.log
```

- 五期通道**所有**日志都在这里
- 国家通道的异常堆栈（CSB 调用失败、签名异常）也在这里
- 反射加载相关问题（TypeLoadException）在 `InsureLog/` 日志开头

## 七、向开发反馈错误时需要附带

如果排查完仍无法解决，向开发反馈时**必须**提供：

1. 完整 `err_msg` / 弹窗文案
2. 报错时间（精确到秒）
3. `insur.ins_log.msgid`（国家通道）或 `InsureLog/YYYYMMDD.log` 报错前后 50 行
4. 当前操作员、就诊号、患者参保类型
5. 部署自检脚本（`docs/deploy_healthcheck.sql`）的最新结果

否则开发无法定位具体上下文。
