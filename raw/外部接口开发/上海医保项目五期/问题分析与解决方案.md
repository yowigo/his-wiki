# 关键问题分析

## 问题根源

主程序使用以下方式加载DLL:

```csharp
targetAssembly = Assembly.Load(File.ReadAllBytes(Path.Combine(path, asseblyName + ".dll")));
foreach (Type clsName in targetAssembly.GetTypes()) { ... } // ← 在这里失败
```

**执行顺序**:
1. `Assembly.Load(byte[])` - 程序集加载到内存
2. **此时我们的静态构造函数还未执行** (因为没访问任何类型)
3. `GetTypes()` - 开始遍历类型
4. 需要加载依赖(NPOI等) - 但 `AssemblyResolve` 还没注册
5. **失败**: `TypeLoadException`

## 为什么我们的方案无效

所有基于静态构造函数的初始化方案都有同样的问题:
- 静态构造函数只有在**首次访问类型**时才执行
- `Assembly.Load(byte[])` 不会触发任何类型的访问
- `GetTypes()` 开始访问类型,但为时已晚

## 可行解决方案

### 方案1: 修改主程序 (推荐但你无法实现)

在 `Assembly.Load` 和 `GetTypes()` 之间添加一行:

```csharp
targetAssembly = Assembly.Load(File.ReadAllBytes(...));

// 触发初始化
var initType = targetAssembly.GetType("zlchs.SH.GJBYB.insure.ModuleInitializer");
initType?.GetMethod("EnsureInitialized")?.Invoke(null, null);

foreach (Type clsName in targetAssembly.GetTypes()) { ... }
```

### 方案2: 不使用子目录 (最简单)

**将所有依赖DLL直接放在主程序目录,不放子目录**

这样.NET运行时会自动找到,无需任何配置。

部署结构:
```
主程序目录/
├── 主程序.exe
├── zlchs.SH.GJBYB.insure.dll
├── NPOI.dll
├── NPOI.OOXML.dll
├── ICSharpCode.SharpZipLib.dll
└── ... 其他所有依赖
```

### 方案3: 使用 app.exe.config (需要主程序支持)

在主程序的配置文件中添加:

```xml
<configuration>
  <runtime>
    <assemblyBinding xmlns="urn:schemas-microsoft-com:asm.v1">
      <probing privatePath="Plugins.WebInsurance\shLibs" />
    </assemblyBinding>
  </runtime>
</configuration>
```

但这需要主程序的配置文件支持。

### 方案4: 创建辅助加载DLL (变通方案)

创建一个极简的 `zlchs.SH.GJBYB.insure.Loader.dll`:

```csharp
// zlchs.SH.GJBYB.insure.Loader.dll
namespace zlchs.SH.GJBYB.insure.Loader
{
    public static class AssemblyHelper
    {
        static AssemblyHelper()
        {
            // 注册全局AssemblyResolve
            AppDomain.CurrentDomain.AssemblyResolve += (sender, args) => {
                // 从shLibs目录加载
                string name = new AssemblyName(args.Name).Name;
                string path = Path.Combine(
                    AppDomain.CurrentDomain.BaseDirectory,
                    "Plugins.WebInsurance", "shLibs", name + ".dll");
                    
                if (File.Exists(path))
                    return Assembly.LoadFrom(path);
                return null;
            };
        }
        
        public static void EnsureLoaded() { }
    }
}
```

然后修改主程序先加载 Loader,再加载真正的DLL。但这也需要修改主程序...

## 实际建议

**由于你无法修改主程序,最可行的方案是:**

1. **临时方案**: 将所有依赖DLL放在主程序目录(不用子目录)
   - 优点: 立即可用,无需任何修改
   - 缺点: 目录混乱

2. **联系主程序开发者**: 请求他们在加载DLL后添加初始化调用:
   ```csharp
   targetAssembly = Assembly.Load(File.ReadAllBytes(...));
   
   // 添加这一行
   var init = targetAssembly.GetType("zlchs.SH.GJBYB.insure.ModuleInitializer");
   init?.GetMethod("EnsureInitialized")?.Invoke(null, null);
   
   foreach (Type clsName in targetAssembly.GetTypes()) { ... }
   ```

3. **或者请求使用 LoadFrom 而不是 Load(byte[])**:
   ```csharp
   // 改为这样加载
   targetAssembly = Assembly.LoadFrom(Path.Combine(path, asseblyName + ".dll"));
   ```
   这样我们的AssemblyResolver就能正常工作。

## 技术限制

.NET Framework 的程序集加载机制决定了:
- 从字节数组加载的程序集没有物理路径
- 静态构造函数只有在访问类型时才执行
- 但 `GetTypes()` 需要先解析依赖才能访问类型
- 这是一个"鸡生蛋蛋生鸡"的问题

**在无法修改主程序的情况下,这个问题无法从DLL内部解决。**
