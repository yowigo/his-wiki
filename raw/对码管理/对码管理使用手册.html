完整操作步骤

🚨SQL 必须遵守的规则

规则 原因
别名必须是 his_code, his_name, his_info 系统生成外层 SQL 时硬编码了这三个列名，写 code/name/info 会报错 column views_data.his_code does not exist
别名必须是 standard_code, standard_name, standard_info 同上，标准侧硬编码了这三个
JSON 字段后面加 ::text 转类型 match_result 表的 his_info/standard_info 是 varchar，json_build_object 返回 json 类型，不转会报 invalid input syntax for type json
机构过滤用 :[org_id] 系统自动替换为当前登录用户的机构 ID
必须过滤 status = 1 避免已停用的数据参与对码

填写完成点确定。如果报错，对照上面的规则逐条排查。

第1步：新增分类

点"新增分类"，弹窗里两个输入框：

输入框 填什么
分类名称 输入一个已有的分类名，该分类就成为父节点
分类子项 你要新建的分类名（子节点）

举例：

  • 想建根节点 药事平台药品对码：上面填 药事平台药品对码，下面留空。系统自动创建这个分类，挂在根下
  • 想在已有分类 医保 下建子分类 药品：上面填 药品，下面填 医保。系统在 医保 节点下创建 药品

后台逻辑：如果"父分类"填的名字还不存在，系统会自动先创建父节点、再创建子节点。如果两者都已经存在且已是父子关系，提示"已存在该分类"。

第2步：编辑对码（配置数据源和 SQL）

选中刚建的分类 → 点"编辑对码"→ 弹出配置弹窗。

弹窗字段：

字段 填什么 本次示例（仅供参考）
对码名称 自己起名 药事平台药品对码
目标数据源 下拉选 HIS 库 药品数据源（drug 域）
三方数据源 下拉选标准库 费用数据源（fee 域）
HIS SQL HIS 侧数据抽取 SQL 见下方
标准 SQL 标准侧数据抽取 SQL 见下方
  1. HIS SQL
SQL
SELECT
    code   AS his_code,
    name   AS his_name,
    json_build_object(
        'strength',     strength,
        'brand_name',   brand_name,
        'manufacturer', manufacturer,
        'fee_type',     fee_type,
        'standard_code', standard_code
    )::text AS his_info
FROM qw_base.b_drug
WHERE status = 1  AND org_id = :[org_id]
  1. 标准 SQL
SQL
SELECT
    standard_code,
    standard_name,
    json_build_object(
        'spec_pack',    spec_pack,
        'pack_unit',    pack_unit,
        'manufacturer', manufacturer,
        'fee_type',     fee_type,
        'pay_ratio',    pay_ratio,
        'drug_type',    drug_type,
        'catalog_code', catalog_code,
        'limit_desc',   limit_desc
    )::text AS standard_info
FROM insur.b_drug_standard
WHERE status = 1  AND org_id = :[org_id]

第3步：自动对码

点"自动对码"，弹窗显示 7 个匹配策略复选框：

复选框 匹配依据 对应列
编号 HIS 编码 = 标准编码 his_code ↔ standard_code
名称 HIS 名称 = 标准名称 his_name ↔ standard_name
附加信息 HIS 附加信息 = 标准附加信息 his_info ↔ standard_info
扩展字段1 ~ 4 对应扩展字段相等 standard_extfield1~4

规则：

  • 可多选，勾选的字段全部相等才算匹配
  • 只对未对码的数据执行，已对码的不受影响
  • 至少勾选一项才能执行

典型用法：

  • 只勾"编号" → 编码相同即自动匹配（最常用）
  • 勾"编号"+"名称" → 编码和名称都相同才算匹配（更严格）
  • 勾"编号"+"附加信息" → 规格/厂家等附加信息也一致才匹配

扩展字段怎么用：

扩展字段的值来自 HIS SQL 和标准 SQL 中返回的 standard_extfield1 ~ standard_extfield4 列。勾选后，系统对这些列做 AND 相等比较，用于精细化匹配。

例如在 HIS SQL 中加上：

SQL
SELECT
    code         AS his_code,
    name         AS his_name,
    ...::text    AS his_info,
    strength       AS standard_extfield1,   -- 规格
    manufacturer   AS standard_extfield2    -- 厂家
FROM qw_base.b_drug
WHERE status = 1 AND org_id = :[org_id]

标准 SQL 中对应加上：

SQL
SELECT
    standard_code,
    standard_name,
    ...::text    AS standard_info,
    spec_pack      AS standard_extfield1,   -- 规格包装
    manufacturer   AS standard_extfield2    -- 厂家
FROM insur.b_drug_standard
WHERE status = 1 AND org_id = :[org_id]

然后勾选"扩展字段1"+"扩展字段2" → 同编码+同规格+同厂家三个条件全部满足才算匹配。

列名必须严格写 standard_extfield1 ~ standard_extfield4，大小写敏感。不需要的字段不返回即可。

勾选后点确定，切换"已对码"Tab 查看结果。

第4步：复核、手动对码

自动对码后，切到"未对码"Tab 查看没匹配上的数据。需要手动逐条补充对照：

操作：点该行的编辑按钮 → 弹出编辑弹窗 → 在"三方名称"输入框中填写标准名称进行检索 → 下拉列表出现匹配项后选择目标 → 保存。

⚠️ 必须先填三方名称，否则下拉列表无数据可选。

其他操作：

场景 操作
匹配错了 点编辑，改 standard_code 和 standard_name，保存
不需要对码 点删除
清掉重来 点清空对码
清空后反悔 点恢复对码

第5步：一键同步

一键同步仅用于将 match_result 对码结果首次写入目标 HIS 库。

🚨 使用前必读：

  • 适用版本：V4.0.8.250227 及之后
  • 仅执行一次：首次将对码结果写入目标库时使用
  • 不一致时：如果执行后发现与原有对码结果不一致，需手动删除目标库对应的 match_result 表数据，再重新执行
  • 操作前仔细阅读弹窗提示，谨慎使用

常见报错及解决

报错信息 原因 解决
column views_data.his_code does not exist HIS SQL 的列别名没写成 his_code/his_name/his_info 改成 AS his_code, AS his_name, AS his_info
invalid input syntax for type json json_build_object 返回 json 类型，和 varchar 列比较时报错 后面加 ::text：json_build_object(...)::text AS his_info
目标库只能是产品数据库 目标数据源选的库 dbtype 不是 2（PostgreSQL） 确认选的 HIS 数据源是 PG 库
已存在该分类 同级下已存在同名分类 换一个分类名
该分类已存在对码数据，无法删除 分类下有 match_result 数据 先点"清空对码"，再删分类
数据源不存在 下拉选的数据源在 ProductDataSource 表里没有配置或实例信息不全 去产品数据源管理页面检查配置
